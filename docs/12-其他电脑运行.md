# 在另一台电脑上运行（依赖与一键安装）

> 现象：把仓库拷到别的电脑，双击 `run.bat` 直接报编译错误。
> 原因基本只有三类：**没装 C++ 工具链 / 没装 CMake / 没装 Vulkan SDK**。
> 现在仓库自带 `setup.bat`，会自动检查并安装缺失依赖，然后构建 + 冒烟。

---

## 1. 最快路径（推荐）

```bat
:: 第一次（会检查并安装依赖，需要管理员权限时会提示）
setup.bat

:: 之后直接玩
run.bat
```

`setup.bat` 做的事：

1. 检查系统（Windows 10/11 x64）；
2. 检查 Git（可选）；
3. 检查 **Visual Studio 2022 + C++ 工作负载**（缺失时用 winget 安装 BuildTools + VCTools）；
4. 检查 **Windows SDK**；
5. 检查 **CMake**（缺失时 winget 安装；没有 winget 则下载便携版到 `.tools\cmake`）；
6. 检查 **Vulkan SDK（可选）**——不装也能构建，只是 `--vulkan-test` 不可用；
7. 构建 Release；
8. 跑 30 帧冒烟测试。

日志写在 `setup.log`。

参数：

| 参数 | 作用 |
|---|---|
| `setup.bat -WithVulkan` | 顺便安装 Vulkan SDK |
| `setup.bat -NoBuild` | 只检查/安装依赖，不构建 |

---

## 2. 手动准备（不想用脚本时）

| 依赖 | 版本 | 说明 |
|---|---|---|
| Windows | 10/11 x64 | 需要 DXGI/D3D11/WIC/XAudio2 |
| Visual Studio 2022 | 17.x | 必须勾选「使用 C++ 的桌面开发」 |
| Windows SDK | 10.0.19041+ | VS 安装器里勾选 |
| CMake | ≥ 3.20 | 命令行或 VS 自带均可 |
| Vulkan SDK | 可选 | 只有跑 `--vulkan-test` 才需要 |

命令：

```bat
build.bat
build\bin\ErMao.exe --frames 30 --noeditor
```

## 3. 这次修掉的真实问题

### 3.1 没装 Vulkan SDK 就编译失败（已修）

以前 `VulkanBackend.cpp` 无条件包含 Vulkan 头文件（`vulkan` 目录下的系统头），
没有 SDK 的机器直接报 `C1083: 无法打开包括文件`。

现在：

- CMake 只有检测到 Vulkan SDK 的头文件存在，才定义 `ERMAO_HAS_VULKAN=1`；
- 没有 SDK 时 `VulkanBackend.cpp` 编译为空实现，`--vulkan-test` 打印一行警告，D3D11 路径完全不受影响。

验证：`set VULKAN_SDK=` 后重新配置构建，能正常出 `ErMao.exe`。

### 3.2 CMake 不在 PATH（已修）

`build.bat` 现在按顺序找：`PATH` → VS 自带 CMake → `.tools\cmake\bin\cmake.exe`，
都找不到才报错，并提示跑 `setup.bat`。

### 3.3 中文注释导致 C4819（已修）

CMake 统一加了 `/utf-8`，在英文/日文 locale 的机器上也不会因为源码编码报错。

### 3.4 构建产物缺失时 `run.bat` 直接失败（已修）

`run.bat` 现在会先调用 `build.bat`，失败时提示先跑 `setup.bat`，并 `pause` 保留窗口。

## 4. 常见错误对照表

| 报错 | 原因 | 处理 |
|---|---|---|
| `C1083: 无法打开包括文件`（Vulkan） | 没装 Vulkan SDK | 更新到最新代码（已用宏隔离），或 `setup.bat -WithVulkan` |
| `C4819: 文件包含不能在当前代码页中表示的字符` | 源码 UTF-8 + 非中文 locale | 更新 CMake（已加 `/utf-8`） |
| `cmake 不是内部或外部命令` | CMake 不在 PATH | `setup.bat`，或把 CMake 加 PATH |
| `MSB8020 / 找不到 v143 工具集` | VS 没装 C++ 工作负载 | VS Installer 勾「使用 C++ 的桌面开发」 |
| `无法打开包括文件: "windows.h"` | 没装 Windows SDK | 同上（VS 安装器里勾 Windows SDK） |
| `LNK1104: 无法打开文件 ErMao.exe` | 上次程序还在运行 | 任务管理器结束 `ErMao.exe` 再构建 |
| `CMake Error: could not find generator "Visual Studio 17 2022"` | 只装了旧版 VS | 装 VS 2022，或改 `-G` 为已装版本 |
| 路径含空格/中文导致奇怪错误 | 老工具链问题 | 把仓库放在 `D:\GameEngine` 这类纯英文路径 |
| winget 下载失败（公司网络） | 代理/防火墙 | 手动装 VS/CMake，或设 `HTTP_PROXY` 后重试 |

## 5. 验证清单（到新电脑后按顺序打勾）

```bat
setup.bat
build\bin\ErMao.exe --frames 30 --noeditor
build\bin\ErMao.exe --demo2d --frames 120
build\bin\ErMao.exe --demo3d --frames 120
build\bin\ErMao.exe --vulkan-test        :: 没装 SDK 时会提示不可用，不算失败
```

全部退出码为 0 即环境 OK。

---

## 6. 离线/内网环境

- VS 2022 离线安装包：VS Installer 里「创建脱机安装」，把布局目录拷到目标机器；
- CMake 便携版：下载 zip 解压到 `.tools\cmake`，`build.bat` 会自动使用；
- Vulkan SDK 不装也行（D3D11 是主路径）；
- 依赖全部 vendored（Dear ImGui 在 `third_party/`），**不需要联网拉第三方库**。

:: 模拟“干净机器”：本地 clone 到别处，清空 VULKAN_SDK 再 setup
git clone D:\GameEngine D:\_ermao_fresh

cd /d D:\_ermao_fresh && setup.bat
