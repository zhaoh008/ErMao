# 博客审稿清单（发布前必须过）

> 硬规则：**如果作者自己读不懂，就不是最终版。**
> 每次准备发一篇，按下面 6 关逐条打勾；任何一关不过，打回重写。

## G1 事实关（可复现）

- [ ] 文中每个命令，我在干净目录跑过一遍，输出与文中一致；
- [ ] 每个截图都是当前版本的真实画面（不是旧图）；
- [ ] 每个代码路径/函数名存在（`tools/docs-check.ps1` 通过）；
- [ ] 数字（帧率、三角形数、可见实例数）与日志一致。

## G2 理解关（作者自测）

- [ ] 我合上文档，能用自己的话讲出这篇的核心问题与答案；
- [ ] 细纲里的 3~5 个自检问题，我至少能答 4 个；
- [ ] 每个公式，我能给出一句「它在解决什么」的白话解释；
- [ ] 每个「为什么」都有答案，没有「书上就这么写」。

## G3 可读关（第一次读的人）

- [ ] 术语首次出现有解释，不假设读者读过前一篇；
- [ ] 每节开头有一句话结论，不是从背景讲起；
- [ ] 段落不超过 5 行，长句拆开；
- [ ] 没有「显然」「众所周知」这种跳步词。

## G4 节奏关

- [ ] 每 800 字左右有一个图/代码/列表，不出现大段纯文字；
- [ ] 代码片段 ≤ 40 行，只留关键行，其余用注释省略；
- [ ] 每篇至少 1 张自制图（不是截图堆砌）+ 1 个可运行实验；
- [ ] 结尾有「如果只记住三件事」。

## G5 冷却关

- [ ] 写完放 48 小时再读一遍；
- [ ] 朗读一遍，凡是读不顺的地方做标记并改写；
- [ ] 删掉至少 10% 的字（通常是形容词和重复解释）。

## G6 读者关

- [ ] 找一个没参与的人（或让 AI 扮读者）读，问 3 个问题：这篇讲了什么？哪段最难懂？你会照着做吗？
- [ ] 对方答不出「讲了什么」→ 结构问题，重写导语；
- [ ] 对方卡在同一段 → 那段加图或例子。

## 发布前最后一眼

- [ ] 标题能在 15 字内说清主题；
- [ ] 开头 3 行有钩子（问题/反常识/结果）；
- [ ] 文末有系列导航与下一篇预告；
- [ ] **我自己愿意把这篇发给朋友看**。

> 记住：博客不是文档的搬运，是「把学习过程讲给三个月前的自己听」。
> 三个月前的我看不懂，就说明还没写好。
