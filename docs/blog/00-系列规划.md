> 素材来源：`docs/lectures/` 27 讲 + 工程文档。目标不是搬运讲义，而是**按读者的问题重新组织**。

## 阅读顺序与依赖

- P1 独立；P2 是后面所有篇的地基；
- P3/P4 可连读（渲染 + 阴影）；P5 独立；
- P6 依赖 P2/P3；P7 依赖 P3；P8 依赖 P3；P9 独立；P10 收尾。

## 每篇的固定结构（模板）

```
1. 钩子：一个具体问题/反常识结论（3 行内）
2. 结论先行：这篇要回答什么，答案是什么
3. 原理：图 + 必要公式（每个公式配一句白话）
4. 代码：≤40 行关键片段，标文件与函数
5. 实验：一条命令，读者能复现
6. 踩坑：2~3 个真实错误（症状/原因/修法）
7. 如果只记住三件事
8. 下一篇预告 + 系列目录
```

## 配图策略

- 每篇 2~4 张：1 张结构/数据流图（自制 SVG）+ 1~2 张运行截图 + 可选对比图；
- 图必须来自当前版本，截图文件名与 `docs/screenshots/` 一致；
- 公式多的篇（P3/P5/P8）优先用「图 + 一句白话」，不堆推导。

## 每篇细纲

### P1 · 为什么要自己写一个游戏引擎

**钩子**：看完 GAMES104 不等于学会——把 22 讲变成能跑、能改、能打包的代码，才算真的学过。

1. **动机：只看不写，等于没学**
   - 课程知识点 vs 工程实现的距离
   - 给自己定三条验收：能跑、能讲、能改
2. **目标与非目标**
   - 教学优先：每个模块对应一讲
   - 明确不做：3A 画质、可视化编程、资产创作
3. **成果一览**
   - 编辑器、2D/3D 幸存者、Vulkan 三角形
   - 用截图和 30 秒 Demo 建立预期
4. **技术选型**
   - C++17 / D3D11 / Dear ImGui / CMake
   - 为什么先 D3D11、Vulkan 放最后
5. **系列阅读路线**
   - 按「骨架 → 渲染 → 动画物理 → 工具 → 游戏 → 进阶」组织
   - 每篇一个可运行实验

- 配图：editor.png, survivors3d.png, survivors.png
- 代码：Engine::MainLoop, docs/01-GAMES104-课程映射.md
- 实验：`build.bat && build\bin\ErMao.exe --demo3d`
- 自检：为什么教学引擎要限制 scope？；D3D11 与 Vulkan 的取舍是什么？；三条验收标准分别对应哪些模块？

### P2 · 引擎骨架：分层、主循环、变换与反射

**钩子**：先搭骨架再谈画面：层怎么分、帧怎么走、数据怎么存。

1. **目录即架构**
   - core → rhi → renderer → scene → gameplay 的单向依赖
   - 为什么 Renderer 不认识 GameObject
2. **固定步长主循环**
   - accumulator 与 kMaxSubSteps
   - 固定 update + 可变 render 的理由
   - 死亡螺旋怎么避免
3. **变换与四元数**
   - TRS 复合顺序、父子矩阵
   - 四元数为什么没有万向锁
   - 归一化阈值与序列化
4. **反射：一份描述驱动两处**
   - ER_COMPONENT + Describe + Field
   - Inspector 与 JSON 共用字段表
   - 字节一致往返的技巧

- 配图：editor.png
- 代码：Engine::MainLoop, scene/Components.h, core/Json.cpp
- 实验：`build\bin\ErMao.exe --test-serialize --frames 2`
- 数学参考：RTR4 §2/§4, Shoemake 1985（四元数）
- 自检：为什么用固定步长而不是直接乘 dt？；反射怎么同时服务 UI 和序列化？；父子变换的乘法顺序为什么是 parent·local？

### P3 · 渲染管线：从三角形到 PBR

**钩子**：一帧画面是怎么从 4×4 矩阵变成一个像素的？

1. **RenderScene：渲染器的输入**
   - 扁平数据结构的意义
   - 为什么不在渲染器里遍历世界
2. **变换与实例化**
   - MVP 与齐次除法
   - 144 B 实例布局、法线矩阵
   - 绕序与背面剔除
3. **PBR：Cook-Torrance**
   - D/G/F 三项分别管什么
   - 一个像素的数值演算（含 ACES/gamma）
   - 金属度/粗糙度怎么影响外观
4. **HDR 与色调映射**
   - 为什么先渲到 RGBA16F
   - ACES 拟合曲线
   - sRGB 与线性空间的坑
5. **调试与踩坑**
   - 法线反向、sRGB 双重转换、深度精度
   - 用 --roughness/--metallic 扫参验证

- 配图：fig-material-grid.png, demo-wave.png
- 代码：shaders/PBR.hlsl, Renderer::OpaquePass, L05 数值演算
- 实验：`ErMao.exe --level arena --play --noeditor --roughness 0.2 --metallic 0.9`
- 数学参考：Cook-Torrance 1982, GGX / Karis 2013, Smith 1967, Schlick 1994, ACES
- 自检：D 和 G 各自解决什么问题？；为什么金属的 F0 是 albedo？；ACES 之前为什么必须在线性空间？

### P4 · 阴影：一张深度图能做什么

**钩子**：阴影贴图不难，难的是偏移、锯齿和自阴影。

1. **把光源当相机**
   - light view-proj 的构造
   - 深度图存的到底是什么
2. **比较与偏移**
   - 为什么需要 bias
   - 斜率相关偏移
   - peter-panning 的取舍
3. **PCF 软阴影**
   - 3×3 采样的平均
   - 采样数 vs 画质
4. **调试视图**
   - 深度图/阴影因子可视化
   - 用 --noshadows 对比

- 配图：fig-shadow-compare.png
- 代码：shaders/Shadow.hlsl, Renderer::ShadowPass
- 实验：`ErMao.exe --level arena --play --noeditor --debugview 2`
- 数学参考：Williams 1978, Reeves 1987（PCF）
- 自检：bias 太大/太小分别出现什么？；PCF 为什么能软化边缘？；阴影贴图分辨率怎么选？

### P5 · 动画、物理与粒子：让世界动起来

**钩子**：骨骼、插值、碰撞、粒子——四套互不相同的数学，拼成一个会动的场景。

1. **蒙皮：S = P·B⁻¹**
   - 绑定姿势与逆绑定
   - LBS 权重混合
   - candy-wrapper 缺陷
2. **动画混合**
   - 关键帧采样
   - 四元数 slerp
   - 状态机与 cross-fade
3. **物理与碰撞**
   - 半隐式欧拉为什么稳定
   - AABB/SAT/球-球
   - 固定步长与穿透
4. **粒子与特效**
   - 发射率/寿命/重力
   - billboard 展开
   - 加法混合与白爆

- 配图：skinning.png, particles.png
- 代码：Skeleton::ComputeSkinning, PhysicsWorld::Step, ParticleEmitter
- 实验：`ErMao.exe --level skinning / --level arena`
- 数学参考：LBS 1988, Shoemake 1985, 半隐式欧拉, SAT 1996, Reeves 1983
- 自检：为什么逆绑定矩阵要乘在骨骼矩阵左边？；半隐式欧拉比显式欧拉稳定在哪？；粒子为什么用加法混合？

### P6 · 编辑器与工具链：ImGui、Gizmo、资源浏览器

**钩子**：引擎不只是运行时，还是一套让人（和 AI）改东西的工具。

1. **即时模式 UI 与 Dock**
   - ImGui 的帧模型
   - DockBuilder 固定布局
2. **拾取**
   - 屏幕射线
   - Möller–Trumbore 求交
3. **三种 Gizmo**
   - 屏幕投影到世界轴
   - 旋转环与缩放方块
   - W/E/R 与相机让位
4. **资源与性能面板**
   - 导入/缩略图/引用
   - CPU/GPU 计时与统计

- 配图：editor.png, gizmo-rotate.png, gizmo-scale.png
- 代码：EditorUI::DrawGizmo, AssetManager::GetMeshThumbnail, Renderer::GetStats
- 实验：`打开编辑器：W/E/R 切 Gizmo，F 聚焦，导入 OBJ`
- 数学参考：Möller–Trumbore, RTR4 拾取章节
- 自检：为什么 Gizmo 要做屏幕恒定大小？；拾取失败的常见原因？；资源缩略图怎么做而不拖慢帧率？

### P7 · 两版幸存者：2D 精灵批与 3D OBJ 管线

**钩子**：同一个玩法，两条渲染路径：一条是 quad 与 UV，一条是 OBJ 与跟随相机。

1. **2D：正交、UV、合批**
   - 正交投影推导
   - 序列帧与透明留白裁剪
   - 按纹理合批
2. **3D：外部模型与材质**
   - OBJ 解析/顶点去重
   - colormap 调色板
   - 相机 yaw/pitch 反解
3. **同构的玩法**
   - 波次/自动攻击/经验/升级
   - 2D 与 3D 的坐标差异
4. **打包：游戏 vs 引擎**
   - game.cfg 的作用
   - Windows 可运行包 vs Linux 源码包

- 配图：survivors.png, survivors3d.png, survivors3d-menu.png
- 代码：Camera2D, Renderer::SpritePass, Survivors3D.cpp
- 实验：`ErMao.exe --demo2d / --demo3d，再打包 dist/AIGame-Windows`
- 数学参考：RTR4 §2.6（正交）, OBJ 规范, RTR4 相机
- 自检：精灵为什么按 layer 排序而不是深度？；OBJ 索引为什么要去重？；游戏包与引擎包差在哪？
