# 第 0 课：从黑屏到第一个三角形【必读·入门】

> 目的：把"屏幕上出现一个三角形"这件事拆成 6 步，每一步只加一样东西。
> 为什么需要这一课：直接看 `Renderer::RenderInternal` 会同时遇到交换链、输入布局、实例化、阴影、后处理——
> 那是"一帧"的全貌，不是"入门"的起点。
>
> 每一步：**改什么 → 应该看到什么 → 不对时先查哪里**。
> 代码都在 `engine/src/rhi/` 与 `engine/src/renderer/`，这里给的是最小骨架。

---

## 步骤 0：窗口 + 清屏

**要理解的东西**：SwapChain / BackBuffer / RTV / Present。

```cpp
// 1) 创建交换链（DXGI_SWAP_EFFECT_FLIP_DISCARD）
// 2) 拿到 back buffer，创建 RTV
// 3) 每帧：
float clear[4] = {0.1f, 0.2f, 0.3f, 1.0f};
ctx->ClearRenderTargetView(rtv, clear);
ctx->OMSetRenderTargets(1, &rtv, nullptr);
swapChain->Present(1, 0);          // 1 = 垂直同步
```

**应该看到**：窗口里是均匀的蓝灰色。

**不对时先查**：

| 现象 | 最可能的原因 |
|---|---|
| 窗口全黑 | `ClearRenderTargetView` 的 RTV 不是当前 back buffer，或 Present 没调用 |
| 颜色不对（偏暗） | `clear` 是线性色，Present 前没有做 sRGB 编码（第 7 讲） |
| 窗口卡死 | 消息泵没跑（`PeekMessage/DispatchMessage`） |

对应代码：`rhi/Device.cpp` 的 `Init` / `BeginFrame` / `EndFrame`。

---

## 步骤 1：全屏三角形（没有顶点缓冲）

**要理解的东西**：`SV_VertexID` 可以凭空生成顶点，用来验证"着色器能跑"。

```hlsl
// 顶点着色器：用 vertexId 生成覆盖全屏的大三角形
float2 uv = float2((vertexId << 1) & 2, vertexId & 2);
o.clip = float4(uv * float2(2, -2) + float2(-1, 1), 0, 1);
```

```cpp
ctx->IASetInputLayout(nullptr);
ctx->IASetPrimitiveTopology(D3D11_PRIMITIVE_TOPOLOGY_TRIANGLELIST);
ctx->Draw(3, 0);
```

**应该看到**：整屏被一个三角形覆盖（像素着色器输出固定颜色）。

**不对时先查**：

| 现象 | 原因 |
|---|---|
| 什么都没有 | 没设置 InputLayout、没用 PSSetShader，或 viewport 不对 |
| 只覆盖一半 | 三角形顶点顺序/坐标错了 |

对应代码：`Sky.hlsl` 与 `Post.hlsl` 的 `VSMain` 就是这么写的（它们不需要顶点缓冲）。

---

## 步骤 2：真正的顶点缓冲 + 索引

**要理解的东西**：顶点布局（InputLayout）必须和 shader 的输入语义**逐字节**对应。

```cpp
struct Vertex { Vec3 position; Vec3 normal; Vec2 uv; };   // 32 字节
D3D11_INPUT_ELEMENT_DESC layout[] = {
    {"POSITION", 0, DXGI_FORMAT_R32G32B32_FLOAT, 0,  0, D3D11_INPUT_PER_VERTEX_DATA, 0},
    {"NORMAL",   0, DXGI_FORMAT_R32G32B32_FLOAT, 0, 12, D3D11_INPUT_PER_VERTEX_DATA, 0},
    {"TEXCOORD", 0, DXGI_FORMAT_R32G32_FLOAT,    0, 24, D3D11_INPUT_PER_VERTEX_DATA, 0},
};
```

**应该看到**：一个立方体（或三角形）出现在屏幕中央。

**不对时先查**：

| 现象 | 原因 |
|---|---|
| 物体被裁掉一半 | 没有投影矩阵，顶点坐标在 [-1,1] 之外 |
| 花屏/错位 | stride 或 offset 写错（例如把 uv 的 offset 写成 8） |
| 背面看不见 | 绕序与剔除方向不匹配（第 4 讲的 `FrontCounterClockwise`） |

对应代码：`renderer/Mesh.cpp` 的 `Create` / `BindVertexBuffers`。

---

## 步骤 3：MVP 矩阵 + 深度

**要理解的东西**：模型 → 世界 → 相机 → 裁剪，以及深度缓冲。

```cpp
Mat4 mvp = camera.ViewProjection() * objectWorld;
ctx->UpdateSubresource(cb, ...);          // 常量缓冲
// 深度：创建 D24S8 的深度模板，OMSetRenderTargets 时一起绑定
```

**应该看到**：立方体有透视（近大远小），遮挡关系正确。

**不对时先查**：

| 现象 | 原因 |
|---|---|
| 物体消失 | 矩阵乘反（`world * viewProj` 而不是 `viewProj * world`） |
| 深度错乱 | 没有深度缓冲，或深度状态没开 |
| 上下颠倒 | 投影矩阵的 Y 符号（D3D 与 OpenGL 的 NDC Y 方向不同） |

对应代码：`renderer/Camera.cpp` 的 `View()/Projection()/ViewProjection()`，推导见第 4 讲。

---

## 步骤 4：常量缓冲 + 光照

**要理解的东西**：`cbuffer` 的 16 字节对齐规则。

```hlsl
cbuffer PerObject : register(b0) {
    float4x4 gWorld;
    float4   gAlbedo;
};   // 64 + 16 = 80 字节，必须手动补齐到 16 的倍数
```

C++ 侧结构体必须逐字节一致（`static_assert(sizeof(T) % 16 == 0)`）。

**应该看到**：立方体有明暗（法线点乘光方向），颜色随参数变化。

**不对时先查**：

| 现象 | 原因 |
|---|---|
| 光照全黑 | 法线没传到 shader，或 `N·L` 为负（光在背面） |
| 颜色错位 | cbuffer 布局与 C++ 不一致（少了一个 float4 就会整体错位） |

对应代码：`rhi/Buffer.h` 的 `ConstantBuffer<T>`，`shaders/PBR.hlsl`。

---

## 步骤 5：回到引擎的"一帧"

现在再看 `Renderer::RenderInternal`，顺序就清楚了：

```
BuildBatches（CPU：视锥剔除 -> 分批 -> 实例数据）
ShadowPass     （深度）
SkyPass        （全屏三角形）
OpaquePass     （实例化 + PBR）
SkinnedPass    （蒙皮）
DebugPass      （线）
PostPass       （全屏三角形 + tone mapping）
```

每个 Pass 都只是"绑定状态 + 画一批顶点"，没有魔法。

## 练习（故意改坏）

1. 把 `kPbrLayout` 里 `TEXCOORD` 的 offset 从 24 改成 16：**预期**贴图错乱/模型变形。
2. 把 `Present(1, 0)` 改成 `Present(0, 0)`：**预期**画面撕裂、帧率上限消失。
3. 把投影矩阵的 `m[2][3]`（w = -z）改成 1：**预期**透视消失/物体反相。

每改一个，先预测，再运行，最后解释——这是最快建立"矩阵/布局直觉"的方式。
