## 按知识链拆解

### A. 引擎骨架（01–02）

| 课程概念 | 代码 | 关键点 |
|---|---|---|
| 引擎是"循环 + 系统" | `Engine::MainLoop` | 消息泵 → 输入快照 → 固定步长仿真 → 渲染 → Present |
| 分层与依赖方向 | `engine/src/*` | `core` 不认识 `scene`；`renderer` 只吃 `RenderItem`，不认识 `GameObject` |
| 初始化/关闭顺序 | `Engine::Init/Shutdown` | 与创建顺序相反释放；D3D11 先 `ClearState` 再重建 |
| 可变步长 vs 固定步长 | `Engine::MainLoop` | 物理 1/60 固定，渲染可变，最多补 5 步，积压超限丢弃 |

**验证**：启动日志会依次打印 Window → Device → Renderer → Assets → World → Editor，正好对应引擎的分层。

### B. 游戏世界（03）

| 课程概念 | 代码 |
|---|---|
| GameObject / Component 组合 | `scene/GameObject.h`、`scene/Components.h` |
| 层级 Transform | `GameObject::SetParent/WorldMatrix`，四元数旋转 |
| 反射（字段元数据） | `scene/Component.h` 中 `TypeInfo/FieldDesc/ER_COMPONENT` |
| 序列化 | `World::ToJson/FromJson`，`core/Json` |
| 延迟销毁 | `World::DestroyObject/ProcessPendingDestruction` |
| 对象所有权 | `World::m_objects`（`unique_ptr` 统一持有）|

**验证**：编辑器里改任一物体的位置/颜色，`Save` 后 `Load`，状态完全一致；Play 后 `Stop` 会回滚到快照。

### C. 渲染（04–07）

| 课程概念 | 代码 | 说明 |
|---|---|---|
| 设备与交换链 | `rhi/Device.cpp` | flip model、resize 时先解绑 RT |
| 顶点/索引/常量缓冲 | `rhi/Buffer.h`、`renderer/Mesh.cpp` | 顶点 32B（pos/normal/uv） |
| 相机与投影 | `renderer/Camera.h` | 右手系、-Z 朝前、深度 [0,1] |
| 实例化 | `Renderer::DrawBatches` | 同 mesh+texture 合批，`DrawIndexedInstanced` |
| 视锥剔除 | `Renderer::BuildBatches` | 8 角点变换 + 6 平面测试，`JobSystem` 并行 |
| 材质与光照 | `shaders/PBR.hlsl` | GGX NDF + Smith 几何 + Schlick 菲涅尔 |
| 阴影 | `Renderer::ShadowPass` + `SampleShadow` | 2048² 正交光源相机 + 3×3 PCF + 法线偏移 |
| 天空 | `shaders/Sky.hlsl` | 逆 VP 重建视线 + 高度渐变 + 太阳盘 |
| 后处理 | `shaders/Post.hlsl` | HDR RGBA16F → ACES → gamma → 暗角 |
| 调试视图 | `PBR.hlsl` 的 `gMisc.x` 分支 | `F3` 循环：阴影系数 / 世界法线 / 基础色 |

**验证**：
1. `F3` 切到阴影视图 → 阴影系数是纯黑白的，能直接看出 PCF 的软化；
2. 改 `Renderer::ComputeLightMatrix` 里光源相机的位置符号，会看到"阴影消失/全黑"——这正是阴影矩阵方向的重要性；
3. `F4` 关阴影，对比地面接触阴影的有无。

### D. 动画（08–09）

| 课程概念 | 代码 | 说明 |
|---|---|---|
| 关键帧 | `TransformKey`（时间 + T/R/S） | 时长、循环 |
| 插值 | `AnimationClip::Sample` | 位置线性、旋转 `Quat::Slerp` |
| 采样器 | `AnimatorComponent::OnUpdate` | 按时间查到区间 → 归一化 → 插值 |
| 节点动画 | 风车（父节点旋转，子节点跟随） | 演示层级继承 |

**省略**：骨骼蒙皮（顶点权重 + 骨骼调色板）、状态机交叉淡入、动画压缩。
**扩展路径**：把 `NodeTrack` 换成 `BoneTrack`，顶点加 `BLENDINDICES/BLENDWEIGHT`，VS 里做 `Σ w_i * Bone_i * v`；采样器完全复用。

### E. 物理（10–11）

| 课程概念 | 代码 |
|---|---|
| 半隐式欧拉 | `PhysicsWorld::Integrate` |
| 球-球 / 球-盒 / 盒-盒 | `SphereVsSphere`、`SphereVsBox`、AABB 最小穿透轴 |
| 冲量 + 恢复系数 + 摩擦 | `ResolveSpherePairs`、`ResolveStaticBoxes` |

**省略**：GJK/EPA、CCD、关节、布料、破坏。
**验证**：Play 后小球从 3m 落下，弹跳高度逐次衰减（恢复系数 0.6），最终 sleep。

### H. 性能与并行（20）

| 课程概念 | 代码 | 说明 |
|---|---|---|
| SoA 实例数组 | `Renderer::InstanceVertex` 数组 | 一次上传、批量提交 |
| 分块并行 | `JobSystem::ParallelFor` | 原子块索引 + 主线程参与 + join |
| 并行剔除 | `Renderer::BuildBatches` | 每个物体独立判定，天然可并行 |
| 加速比可观测 | `JobSystem::Benchmark` + Stats 面板 | 串行 vs 并行 ms |

**取舍**：这里用"每次 ParallelFor 临时拉线程"的模型（代码短、无唤醒丢失风险），
工业引擎会用常驻线程池 + fiber 依赖图 + 无锁队列，文档 `02-分章讲解.md` 第 20 节给了对比。

## 未实现部分的诚实说明

| 讲 | 为什么没做 | 若要补齐，第一步是什么 |
|---|---|---|
| 09 动画进阶 | 时间/复杂度 | 加 `BlendSpace` 与 `CrossFade`，在采样器上做两层求值加权 |
| 12 特效 | 需要粒子系统与排序 | GPU 粒子：结构化缓冲 + 计算着色器 + 加法混合 |
| 17 进阶 AI | 行为树不是刚需 | `BehaviorTree` 节点（Sequence/Selector/Condition/Action）+ JSON 描述 |
| 18/19 网络 | 需要第二个进程与协议 | 先做"帧同步 + 输入缓冲"，再做状态同步与插值 |
| 21 GI | 成本高（需要探针/光追） | 先做光照探针（球谐）或 SSGI，再谈 Lumen |
| 22 GPU Driven | 需要间接绘制 + GPU 剔除 | 用 `DrawIndexedInstancedIndirect` + 计算着色器剔除 |

这些缺口不影响已实现部分的教学价值：**每个已完成系统都能在编辑器里点、在代码里读、在画面上看**。
