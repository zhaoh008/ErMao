## 1. 两种架构

| 架构 | 权威方 | 优点 | 缺点 |
|---|---|---|---|
| P2P | 玩家之间 | 延迟低 | 作弊、状态不一致 |
| 客户端-服务器 | 服务器 | 防作弊、状态统一 | 服务器成本、需要预测 |

竞技游戏几乎都是"服务器权威 + 客户端预测"。

---

## 2. 快照同步

服务器每 `T` 毫秒发一次世界状态快照（位置/血量/朝向），客户端：

1. **插值**：渲染比服务器慢 `T`（interpolation delay），在两个快照之间插值，画面平滑；
2. **外推**：用速度预测未来位置，延迟补偿但会"拉回"。

数学：设快照时刻 `t0, t1`，客户端渲染时刻 `t_r`：

```
α = (t_r - t0) / (t1 - t0)
pos = lerp(pos0, pos1, α)
```

`t_r` 必须落后于最新快照（`t_r = now - T`），否则 α > 1 需要外推。

---

## 3. 客户端预测与回滚

本地玩家输入立即生效（否则手感差），同时发给服务器：

```
预测：本地先按输入模拟
对账：服务器回包带"权威状态 + 最后确认的输入序号"
若预测与权威不一致 → 回滚到权威状态，重放未确认的输入
```

这就是 **rollback netcode**，格斗游戏常用。
需要"确定性模拟"：同样的输入 + 同样的初始状态 → 同样的结果（浮点确定性极难，
工业界用定点数）。

## 4. 带宽估算

一个实体：位置 12B + 朝向 4B（压缩四元数）+ 血量 4B ≈ 20B。
100 个实体 × 20Hz × 20B = 40KB/s ≈ 320kbps——还没算包头与可靠性层。

优化：
- 增量（只发变化的字段）；
- 量化（位置用 16 位定点，误差 1cm）；
- 优先级（视野内高、视野外低）。
