# 第 2 讲：分层与依赖方向【必读】

> 对应 GAMES104 第 2 讲（引擎架构）。
> 代码：`engine/src/` 的目录结构 + 各层头文件的 `#include`。
> 目标：说清楚"为什么引擎要分层""依赖方向错了会怎样""本工程哪些地方妥协了"。

---

## 1. 分层的目标

一句话：**低层不知道高层存在**。

```
core       数学/JSON/日志/计时/文件/JobSystem     —— 不认识任何渲染、场景
  ↑
rhi        D3D11 设备/缓冲/纹理/RT/Shader/截图     —— 只认识 D3D11
  ↑
renderer   相机/网格/批处理/阴影/后处理/视口        —— 只吃 RenderScene，不认识 GameObject
  ↑
scene      World/GameObject/Component/反射/序列化   —— 不认识渲染器
  ↑
gameplay   physics/ai/animation/game               —— 组合玩法
  ↑
editor     ImGui 面板                              —— 能看见所有层
  ↑
runtime    Engine 主循环、Packager                 —— 组装与生命周期
```

**证据**：`renderer/Renderer.h` 只 include `renderer/*`、`rhi/*`、`core/*`，
没有 `scene/`；`scene/World.h` 没有 `d3d11.h`。

---

## 2. 为什么依赖方向重要

1. **可测试**：`core/Math` 不依赖 D3D，可以单独写单测；
2. **可替换**：理论上把 `rhi` 换成 Vulkan，`renderer` 以上不用动；
3. **编译时间**：低层改一行，高层全重编是必然的；反过来高层改动不影响低层；
4. **心智负担**：看 `scene` 的代码不需要懂 D3D11。

反例：如果 `World` 里直接 `#include <d3d11.h>` 并创建缓冲，
那么"序列化一个场景"也要连着显卡上下文，测试和服务器端复用都不可能。

---

## 3. 本工程的妥协（要诚实）

| 现象 | 原因 | 影响 |
|---|---|---|
| `Renderer` 直接暴露 `ID3D11ShaderResourceView*` | 编辑器要 `ImGui::Image` | RHI 不是真抽象，换后端要改编辑器 |
| `scene/World.cpp` 注册 `game/` 的组件 | 组件注册集中在 World::Init | scene 依赖 game，方向反了 |
| `game/SkinningDemo.cpp` 调 `Renderer::CreateSkinnedMesh` | 关卡需要 GPU 资源 | game 依赖 renderer（可接受，game 本就在上层） |
| `editor/EditorUI.cpp` 包含渲染器头 | 视口/缩略图 | editor 是最高层，允许 |

`docs/06` 已把这些登记为"已知差距"，不在文档里宣称"RHI 可换后端"。

---

## 4. 数据流

```
输入 -> World(组件更新) -> RenderScene -> Renderer -> GPU
                     └-> 物理/AI/动画
```

**关键边界是 `RenderScene`**：

```cpp
struct RenderScene {
    std::vector<RenderItem> items;
    std::vector<PointLightRender> pointLights;
    std::vector<SkinnedDraw> skinned;
    Vec3 sunDirection; ...
};
```

`World::BuildRenderScene` 把"游戏世界"翻译成"渲染需要的最小数据"；
渲染器只读它，不知道实体、组件、脚本。

好处：渲染可以在没有 World 的情况下测试（构造一个 RenderScene 即可），
将来做 GPU Driven（第 22 讲）时，只需改 `Renderer` 内部，`World` 不变。

## 7. 练习（故意改坏）

1. 在 `renderer/Renderer.h` 里 `#include "scene/World.h"`：**预期**能编过，但依赖方向反了；
   试着在 `scene/World.h` 里再 include `renderer/Renderer.h`，会得到循环依赖——这就是为什么要单向。
2. 把 `RenderScene` 换成直接传 `World*`：**预期**渲染器无法脱离场景单测，`--level` 逻辑也要跟着改。
3. 在 `core/Math.h` 里 include 任何 D3D 头：**预期** `core` 层不再纯净，编译时间变长。
