# 第 14 讲：序列化与反射——一份描述驱动 UI 与存档【必读】

> 对应 GAMES104 第 14 讲（工具链进阶）。
> 代码：`scene/Component.h`（反射/字段描述）、`scene/Component.h`、`core/Json.*`、`scene/World.cpp`（ToJson/FromJson）。
> 目标：说明"为什么检视器不需要为每个组件写一遍 UI"，以及"场景 JSON 如何做到字节级往返"。

---

## 1. 问题

如果有 20 种组件，朴素做法要写：

- 20 个检视器面板；
- 20 段 save/load 代码；
- 每加一个字段，改三处（结构体、UI、序列化）。

反射要解决的是：**字段只声明一次，UI 与序列化自动跟上**。

```
   Describe(TypeInfo&)   ← 每个组件写一次
        │
        ├──▶ 检视器：按 FieldType 生成控件
        └──▶ JSON：   按 FieldDesc 读写字段
                     │
                     ▼
              World::ToJson / FromJson（场景快照、PIE 回滚）
```

---

## 2. 设计

### 2.1 字段描述

```cpp
struct FieldDesc {
    const char* name;
    FieldType   type;     // Bool / Int / Float / Vec3 / Vec4 / Color / String / ...
    void*       member;   // 指向成员的指针（成员指针转 void*）
    const char* label;    // UI 显示名
    float       min, max;
};
```

每个组件实现 `Describe(TypeInfo&)`：

```cpp
void MeshRenderer::Describe(TypeInfo& t) {
    t.Field("albedo", FieldType::Color, &MeshRenderer::albedo, "基础色");
    t.Field("roughness", FieldType::Float, &MeshRenderer::roughness, "粗糙度", 0.04f, 1.0f);
    ...
}
```

宏 `ER_COMPONENT(Class, "Name")` 负责声明 `Describe` 与注册类型。

### 2.2 检视器

```cpp
for (const FieldDesc& f : type.fields) {
    switch (f.type) {
        case FieldType::Float: ImGui::DragFloat(f.label, (float*)f.member, 0.01f, f.min, f.max); break;
        case FieldType::Color: ImGui::ColorEdit4(f.label, (float*)f.member); break;
        ...
    }
}
```

新增字段 → 注册一行 → UI 与 JSON 同时生效。

### 2.3 序列化

```cpp
JsonValue::Object obj;
for (const FieldDesc& f : type.fields) obj[f.name] = ToJson(f);
```

读回时按类型 `FromJson`。**字段名是键**，所以改名会破坏旧存档——
工业做法是加版本号与迁移函数（本工程未做，作为差距记录）。

## 3. 字节级往返：两个坑

### 3.1 浮点格式

`%.6g` 打印再解析会差 1 ULP（第 4 位有效数字就丢精度）。修正：

- 输出用 C++17 `std::to_chars` 的**最短往返表示**（float 路径）；
- 解析用 `strtof`（正确舍入到 float）。

```cpp
const float f = static_cast<float>(v);
if (static_cast<double>(f) == v) res = std::to_chars(buf, end, f);
else                             res = std::to_chars(buf, end, v);
```

### 3.2 四元数归一化

`SetRotation` 每次都 `.Normalized()`，而"已归一化的四元数再归一化"仍会漂 1 ULP，
于是每次"加载→保存"都变。修正：只在偏差 > 1e-4 时归一化。

```cpp
const float length = sqrt(q.x*q.x + ...);
m_rotation = (fabs(length - 1) > 1e-4f) ? q.Normalized() : q;
```

修完后的自检输出：

```
[自检] 序列化往返: 17 -> 17 个对象，再次往返稳定=是，首次字节一致=是
```

**为什么断言"再往返一次稳定"**：第一次加载允许一次性的归一化漂移；
第二次必须完全一致，否则说明序列化不是幂等的（有隐藏状态在每次加载时改变）。

## 4. Play-In-Editor（PIE）

```cpp
void Editor::EnterPlayMode(World& world) {
    m_snapshot = world.ToJson().Dump();   // 快照
    m_playing = true;
}
void Editor::ExitPlayMode(World& world) {
    m_playing = false;
    JsonValue root = JsonValue::Parse(m_snapshot, &error);
    world.FromJson(root);                 // 回滚
}
```

- 快照是**整个场景的 JSON**（几十 KB），比"记录每个物体的增量"简单可靠；
- 回滚 = `Clear + FromJson`，对象指针全部失效——所以任何缓存的 `GameObject*` 都要在 PIE 后重查
  （审核 P2-20 就是抓到了 `m_player` 悬垂）。
