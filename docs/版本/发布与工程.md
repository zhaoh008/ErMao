# 发布与工程

> 这一篇回答：**怎么打包、怎么发版、仓库怎么维护、素材从哪来**。
> 构建与运行见 [构建与运行](构建与运行.md)；版本历史见 [版本记录](版本记录.md)。

## 1. 两种包：引擎包 vs 游戏包

**引擎发布和游戏发布是两件事**：

| 类型 | 产物 | 用途 | 含编辑器 |
|---|---|---|---|
| **引擎包** | `dist/ErMao-Windows/` | 给开发者：打开编辑器、做关卡、导资源 | 是 |
| **2D 游戏包** | `dist/ErMaoSurvivors-Windows/` | 给玩家：2D 幸存者，双击即玩 | 否 |
| **3D 游戏包** | `dist/ErMaoSurvivors3D-Windows/` | 给玩家：3D 幸存者，双击即玩 | 否 |

游戏包的 exe 与引擎包是**同一个二进制**，区别只在 exe 旁的 `game.cfg`：

```ini
game=ErMaoSurvivors
level=survivors
editor=0
play=1
```

`Engine::Run` 先读 `game.cfg`，命令行参数优先级更高，所以调试时仍可
`ErMaoSurvivors.exe --level arena --frames 60`。

## 2. Windows 游戏包

菜单：`文件 → 打包 → 打包游戏：二毛幸存者（Windows）`
命令行：`build\bin\ErMao.exe --package-game windows --frames 2`

产物（`dist/ErMaoSurvivors-Windows/`）：

```
ErMaoSurvivors.exe      ← 游戏可执行文件（引擎 + 游戏逻辑）
game.cfg                ← 启动配置（关卡/模式）
assets/                 ← 2D 精灵、场景、程序化资源
shaders/                ← 运行时编译的 HLSL
run.bat                 ← 双击启动
README.txt
LICENSE-2D-ASSETS.txt   ← 素材许可（见 §7）
```

**已验证**：把整个目录拷到别处，能正常启动、显示主菜单、进入战斗。
3D 包结构相同，`level=survivors3d`，资源里多出 `models/kenney/`、`textures/kenney/`、`particles/`。

## 3. Linux：为什么没有可执行文件

游戏逻辑、2D 数据、资源都是跨平台的，但**平台层与图形层是 Win32 + D3D11**：

- `platform/Window` 用 `CreateWindowExW`、消息泵、`GetOpenFileNameW`；
- `rhi/` 直接持有 `ID3D11Device`、`IDXGISwapChain`；
- 着色器是 HLSL，由 `D3DCompile` 运行时编译。

所以 **Linux 二进制在当前版本不存在**，打包器也不会假装有。
Linux 包是源码包：`dist/ErMaoSurvivors-Linux-Source/`（2D）与
`dist/ErMaoSurvivors3D-Linux-Source/`（3D），包含：

```
engine/            ← 引擎 + 游戏源码
third_party/imgui  ← UI
docs/              ← 讲义
CMakeLists.txt
game.cfg
build.sh           ← 环境检查脚本（打印还需要补什么）
README-LINUX.md    ← 移植清单
```

补齐 Linux 运行时的 5 步：

1. 平台层：GLFW/SDL2 替换窗口与输入；
2. 图形层：`rhi/` 增加 Vulkan 或 OpenGL 后端；
3. 着色器：HLSL → SPIR-V（DXC）或 GLSL；
4. UI：ImGui 的 `imgui_impl_glfw` + `imgui_impl_vulkan`；
5. 资源：`assets/`、`shaders/` 随包复制，`game.cfg` 指定关卡。

这是本工程**明确记录的能力边界**，不是打包脚本的 bug。

## 4. 引擎包

菜单：`文件 → 打包 → 打包 Windows`
命令行：`build\bin\ErMao.exe --package windows --frames 2`

产物含编辑器与全部关卡，启动后是编辑器界面（可 F5 进 PIE）。

## 5. 打包器做了什么

`runtime/Packager.cpp`：

- `CopyTree`：递归复制 `shaders/`、`assets/`；
- `WriteText`：写 `game.cfg`、`run.bat`、`README`、许可文件；
- `dist/GENERATED_DO_NOT_EDIT.txt`：标记 dist 是构建产物，不要手改；
- Linux 包的 `build.sh` 只做环境检查并 `exit 0`，避免用户误以为环境坏了。

## 6. 发布前检查清单

```bat
build.bat
build\bin\ErMao.exe --package windows --frames 2
build\bin\ErMao.exe --package-game windows --frames 2
dist\ErMaoSurvivors-Windows\ErMaoSurvivors.exe
build\bin\ErMao.exe --package-game linux --frames 2
build\bin\ErMao.exe --demo2d --frames 300
build\bin\ErMao.exe --test-serialize --frames 2
```

- [ ] `game.cfg` 的 `level` 与本包游戏一致；
- [ ] `assets/sprites/` 里有贴图与许可文件；
- [ ] 游戏包目录整体改名/移动后仍能运行（不依赖工程目录）；
- [ ] `CHANGELOG.md` 的 `Unreleased` 已更新，`版本记录.md` 已补版本行；
- [ ] `pwsh -File tools\docs-check.ps1` 通过。

## 7. Git 工作流

### 7.1 现状

- 稳定分支 `main`：随时可 `build.bat`、可打包；
- 源码、资源、讲义、文档都在版本控制里；
- `build/`、`dist/`、`.staging/`、日志、`imgui.ini`、AI 脚本输出不入库（`.gitignore`）；
- 行尾由 `.gitattributes` 约束：源码/文档 LF，`.bat/.ps1` CRLF，图片/音频/SPIR-V 二进制；
- 远程仓库：`origin`（GitHub）；发布标签按 `CHANGELOG.md` 补打。

### 7.2 分支模型

| 分支 | 规则 |
|---|---|
| `main` | 随时可构建、可打包；不直接写大功能 |
| `feat/*` | 新功能，从 `main` 切出，合并前 rebase |
| `fix/*` | 修复 |
| `docs/*` | 文档/讲义 |
| `ai/*` | AI 生成的改动，单独分支便于整体回滚 |

```bat
git switch main
git pull
git switch -c feat/vulkan-opaque
:: 开发...
git commit -m "feat(vulkan): migrate opaque pass to RHI"
git switch main
git merge --no-ff feat/vulkan-opaque
```

### 7.3 提交信息（Conventional Commits）

```
<type>(<scope>): <summary>
```

| type | 用途 | 例子 |
|---|---|---|
| `feat` | 新功能 | `feat(audio): XAudio2 WAV playback` |
| `fix` | 修复 | `fix(2d): missing ImGui EndFrame` |
| `docs` | 文档 | `docs(lectures): math references per lecture` |
| `refactor` | 重构（不改行为） | `refactor(rhi): split device interface` |
| `perf` | 性能 | `perf(renderer): batch sprites by texture` |
| `build` | 构建/CMake | `build: add vulkan-1 link dir` |
| `chore` | 杂项 | `chore(repo): add gitattributes` |

AI 参与的提交在 body 里写清工具、提示词摘要、验证方式。

### 7.4 标签与发布

每个可运行状态打附注标签：

```bat
git tag -a v0.8.0 -m "AI 优先接口"
git tag -n
git push origin --tags
```

发布时把 `dist/` 里的包作为 release attachment（dist 不进 Git）。

### 7.5 钩子与 CI

```bat
git config core.hooksPath .githooks
```

`pre-commit`：拒绝 `build/`、`dist/`、`*.log` 入库；跑 `tools/docs-check.ps1`，
文档引用了不存在的 `.cpp/.h/.hlsl` 就拦下。

`.github/workflows/build.yml`（windows-2022）：

1. CMake 配置 + Release 构建；
2. `docs-check.ps1`；
3. 30 帧无编辑器冒烟。

Vulkan 代码在没有 SDK 时由 CMake 宏自动跳过，CI 不强制装 Vulkan SDK。

### 7.6 常用操作

```bat
git restore .                                   :: 撤销未提交改动
git reset --soft HEAD~1                         :: 撤销上次提交（保留改动）
git log -p -- engine/src/renderer/Renderer.cpp  :: 单文件历史
git checkout v0.7.0 -- engine/src/platform/Audio.cpp  :: 找回误删文件
git diff v0.7.0..v0.8.0 --stat
```

### 7.7 与 AI 协作的约定

- 一个逻辑一个 commit，保证能单独回滚；
- AI 生成的报告（`agent-report.json` 等）不入库，只入库命令脚本（`agent/examples/*.json`）；
- 文档改动后重新生成 HTML 文档站，再一起提交；
- 提交前贴出构建与关键 demo 的日志摘要。
