# 打包与发布：引擎包 vs 游戏包

> 结论先说：**引擎发布和游戏发布是两件事**。
> 引擎包 = 编辑器 + 运行时；游戏包 = 某款游戏的可执行文件 + 资源 + 启动配置。
> 本工程两种都支持，菜单在 `文件 → 打包`。

---

## 1. 两种包

| 类型 | 产物 | 用途 | 是否含编辑器 |
|---|---|---|---|
| **引擎包** | `dist/ErMao-Windows/` | 给开发者用：打开编辑器、做关卡、导入资源 | 是（默认启动编辑器） |
| **游戏包** | `dist/ErMaoSurvivors-Windows/` | 给玩家用：双击即玩，看不到编辑器 | 否 |

游戏包的 exe 与引擎包是**同一个二进制**，区别在 `game.cfg`：

```ini
game=ErMaoSurvivors
level=survivors
editor=0
play=1
```

引擎启动时读取 exe 同目录的 `game.cfg`（`Engine::Init`）：

- `level`：默认关卡（`survivors` / `arena` / `thirdperson` / `skinning` / `cull`）；
- `editor=0`：不创建编辑器 UI，直接进入游戏；
- `play=1`：启动即运行（游戏状态机从主菜单开始）。

命令行参数优先级更高，所以调试时仍可 `ErMaoSurvivors.exe --level arena --frames 60`。

---

## 2. Windows 游戏包（可直接玩）

菜单：`文件 → 打包 → 打包游戏：二毛幸存者（Windows）`
命令行：`build\bin\ErMao.exe --package-game windows --frames 2`

产物（`dist/ErMaoSurvivors-Windows/`）：

```
ErMaoSurvivors.exe      ← 游戏可执行文件（引擎 + 游戏逻辑）
game.cfg                ← 启动配置（关卡/模式）
assets/                 ← 2D 精灵、场景、程序化资源
shaders/                ← 运行时编译的 HLSL
run.bat                 ← 双击启动
README.txt
LICENSE-2D-ASSETS.txt   ← 素材许可（Kenney CC0 + 用户提供的角色包）
```

**已验证**：把整个目录拷到别处运行，游戏能正常启动、显示主菜单、进入战斗。

---

## 3. Linux：为什么没有可执行文件

游戏逻辑、2D 渲染数据、资源都是跨平台的，但**平台层与图形层是 Win32 + D3D11**：

- `platform/Window` 用 `CreateWindowExW`、消息泵、`GetOpenFileNameW`；
- `rhi/` 直接持有 `ID3D11Device`、`IDXGISwapChain`；
- 着色器是 HLSL，由 `D3DCompile` 运行时编译。

所以 **Linux 二进制在当前版本不存在**，打包器也不会假装有。
`打包游戏：二毛幸存者（Linux 源码包）` 产出的是：

```
ErMaoSurvivors-Linux-Source/
  engine/            ← 引擎 + 游戏源码（含 Survivors 玩法与 2D 渲染）
  third_party/imgui  ← UI
  docs/              ← 讲义
  CMakeLists.txt
  game.cfg           ← 同一个配置
  build.sh           ← 环境检查脚本（会打印还需要补什么）
  README-LINUX.md    ← 移植清单
```

补齐 Linux 运行时的 5 步（README-LINUX.md 里也写了）：

1. 平台层：GLFW/SDL2 替换窗口与输入；
2. 图形层：`rhi/` 增加 Vulkan 或 OpenGL 后端；
3. 着色器：HLSL → SPIR-V（DXC）或 GLSL；
4. UI：ImGui 的 `imgui_impl_glfw` + `imgui_impl_vulkan`；
5. 资源：`assets/`、`shaders/` 随包复制，`game.cfg` 指定关卡。

这是本工程**明确记录的能力边界**，不是打包脚本的 bug。

---

## 4. 引擎包（给开发者）

菜单：`文件 → 打包 → 打包 Windows`
命令行：`build\bin\ErMao.exe --package windows --frames 2`

产物包含编辑器与全部关卡，启动后是编辑器界面（可 F5 进 PIE）。

---

## 5. 打包器做了什么

`runtime/Packager.cpp`：

- `CopyTree`：递归复制 `shaders/`、`assets/`（std::filesystem）；
- `WriteText`：写 `game.cfg`、`run.bat`、`README`、许可文件；
- `dist/GENERATED_DO_NOT_EDIT.txt`：标记 dist 是构建产物，不要手改；
- Linux 包的 `build.sh` 只做环境检查并 `exit 0`，避免用户误以为环境坏了。

---

## 6. 发布前检查清单

```bat
:: 1. 构建
build.bat

:: 2. 引擎包
build\bin\ErMao.exe --package windows --frames 2

:: 3. 游戏包（Windows）
build\bin\ErMao.exe --package-game windows --frames 2
dist\ErMaoSurvivors-Windows\ErMaoSurvivors.exe

:: 4. 游戏包（Linux 源码）
build\bin\ErMao.exe --package-game linux --frames 2

:: 5. 冒烟
build\bin\ErMao.exe --demo2d --frames 300
build\bin\ErMao.exe --test-serialize --frames 2
```

检查项：

- [ ] 游戏包目录里没有 `imgui.ini`（首次启动自动生成，属正常）；
- [ ] `game.cfg` 的 `level` 与本包游戏一致；
- [ ] `assets/sprites/` 里有贴图与许可文件；
- [ ] 把游戏包目录整体改名/移动后仍能运行（不要依赖工程目录）。
