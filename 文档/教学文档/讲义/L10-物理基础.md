## 1. 一个箱子从 3 米高掉下来

把木箱（半高 0.5 m）放在 `y = 3`，松手，它要落 2.5 m。理想情况下约 0.71 秒后"咚"一声停在地上；实际常看到三件事：

- 落地前有一帧箱子陷进地面，下一帧又被拉回表面；
- 停住后箱子在几厘米的高度上抖几下；
- 同样参数第二次运行，弹起高度和第一次不一样；换一台帧率不同的机器更明显。

这不是重力公式写错了。重力只回答"这一时刻加速度是多少"；真正决定箱子在哪里的，是**每一帧用多大的步子把加速度变成位置**。这一步叫数值积分，本讲先把它写成最朴素的版本，再让它在具体数字上失败。
## 2. 最简实现：显式欧拉
**概念伪代码**（不是仓库实现）：
```cpp
struct Body { Vec3 pos; Vec3 vel; };
const Vec3 g{0, -9.81f, 0};

void StepExplicit(Body& b, float dt) {
    b.pos += b.vel * dt;   // 先用旧速度走一段
    b.vel += g * dt;       // 再让重力改速度
}
```

它看起来完全合理：位移 = 速度 × 时间，速度变化 = 加速度 × 时间。只有一个细节被藏起来了——**先走后加速**，意味着这一帧的位置用的是"上一帧的速度"。
## 3. 让它具体地失败

### 3.1 大 `dt` 会穿地
假设箱子落地前速度是 `v = -4 m/s`：

| `dt` | 一步走多远 | 后果 |
|---|---|---|
| 1/60 s | 0.067 m | 最多陷进地面 6.7 cm，下一帧拉回 |
| 1/15 s | 0.267 m | 能穿过 20 cm 厚的薄平台 |
| 0.25 s | 1.0 m | 直接越过整块地板，检测不到接触 |

"穿透"（Tunneling）不是箱子真的穿过去了，而是**采样太稀**：两次采样之间它已经在地面以下，代码直到下一帧才发现，于是你看到一帧陷进去、下一帧弹回来。检测只发生在采样点上，速度越快、步长越大，越容易漏掉中间的碰撞。
### 3.2 不同帧率得到不同结果
还是 1 秒自由落体，初速度为 0，只改积分步长 `h`，用显式欧拉（暂时不加阻尼）：

| `h` | 1 秒后高度 | 与解析解 `-4.905 m` 的差 |
|---|---|---|
| 1/60 | -4.823 m | +0.082 m（少掉） |
| 1/30 | -4.742 m | +0.164 m |
| 1/15 | -4.578 m | +0.327 m |
| 0.25 | -3.679 m | +1.226 m |

解析解是 `y = ½gt² = -4.905 m`。显式欧拉的误差可以写成 `-½gh·t`：`h` 越大，误差线性变大。也就是说，**同样的重力、同样的 1 秒，帧率不同，箱子落到的位置不同**。这对"手感"和"联机同步"都是硬伤。
### 3.3 能量会凭空变多
自由落体本身不守恒机械能（势能变动能），所以别拿它论证"能量增加"。真正暴露问题的是往复系统，例如刚度为 `ω²` 的弹簧：
```
显式欧拉：
  x_{n+1} = x_n + h·v_n
  v_{n+1} = v_n - h·ω²·x_n

写成矩阵 A = [ 1      h    ]
             [ -ω²h   1    ]
det(A) = 1 + ω²h²，特征值模长 = sqrt(1 + ω²h²) > 1
```

每步振幅都乘 `sqrt(1+ω²h²)`。取 `ω = 10 rad/s`、`h = 0.1 s`，每步乘 `sqrt(2) ≈ 1.414`——**一步就多 41% 振幅**。注意：对无阻尼振子，显式欧拉对任意 `h > 0` 都在增长，只是 `h` 小时增长慢；加阻尼才可能把它压住。半隐式欧拉（下一节）在同样条件下 `det(A) = 1`，稳定条件是 `ωh < 2`。

如果箱子已经陷进地面，代码直接令 `pos.y = halfExtent`，但速度仍是向下的 `-4 m/s`，下一帧它又会陷进去。位置修正没有配套的速度修正，就会表现为持续抖动。
## 4. 逐步引入正式方案

### 4.1 半隐式欧拉：先更新速度，再用新速度走
**概念伪代码**（本工程采用这个顺序）：
```cpp
void StepSemiImplicit(Body& b, float dt) {
    b.vel += g * dt;       // 1) 先让速度吃到这一帧的加速度
    b.pos += b.vel * dt;   // 2) 再用"新速度"走
}
```

它只把两行换了顺序，但含义完全不同：位置用的是**这一帧结束时的速度**。

对弹簧 `a = -ω²x`，半隐式写成矩阵：
```
A = [ 1 - ω²h²    h  ]
    [ -ω²h        1  ]
det(A) = 1
```

只要 `ωh < 2`，特征值在单位圆上，振幅不增长。自由落体时它也不是"精确"的：1 秒后会比解析解多掉 `½|g|h`（`h = 1/60` 时约 8 cm），但误差随 `h → 0` 收敛，且不会像显式欧拉那样在往复系统里指数放大。

本工程的积分顺序就是这段（**源码节选**，`PhysicsWorldSim.cpp:102-106`）：
```cpp
if (body->useGravity) body->velocity.y += m_gravity * dt;
body->velocity *= (1.0f - 0.02f); // 线性阻尼
Vec3 pos = object->WorldPosition();
pos += body->velocity * dt;
SetWorldPosition(object, pos);
```

注意第二行：**本工程还乘了 0.98**。这不是半隐式欧拉的一部分，而是一个每步固定 2% 的速度衰减。它会让"用解析解验算"对不上，后面第 6 节会具体算给你看。
### 4.2 固定步长：别让 `dt` 随帧率变
只要 `dt` 来自"上一帧花了多久"，同一套参数在 30 fps 和 144 fps 下就会得到不同轨迹。解决办法是**固定步长（Fixed Timestep）**：物理永远用 `h = 1/60 s` 推进，渲染帧率只决定这一帧要补几步。

**源码节选**（`runtime/Engine.cpp:497-512`）：
```cpp
m_accumulator += dt;
int steps = 0;
while (m_accumulator >= kFixedDt && steps < kMaxSubSteps) {
    m_world.FixedUpdate(kFixedDt);
    m_accumulator -= kFixedDt;
    ++steps;
}
if (steps == kMaxSubSteps) m_accumulator = 0.0f; // 防死亡螺旋
m_world.Update(dt);
```

本工程 `kFixedDt = 1/60`、`kMaxSubSteps = 5`。这和第 1 讲的结论是同一个：固定步长保证**可复现**，不保证**绝对精确**；它仍然有离散误差，只是误差不再随帧率漂移。累加器、丢弃积压和"固定步长不是无条件稳定"的细节见第 1 讲。
### 4.3 接触检测：先回答"有没有碰到"
本工程只处理两类形状（`RigidBodyComponent::Shape`）：

- 球：中心 `c`、半径 `r`，与地面 `y = 0` 接触的条件是 `c.y - r < 0`；
- 盒：中心 `c`、半尺寸 `e`，与地面接触的条件是 `c.y - e.y < 0`。

碰到之后先把物体推回表面，再处理速度。**源码节选**（`PhysicsWorldSim.cpp:127-139`，球分支）：
```cpp
const float bottom = pos.y - body->radius;
if (bottom < 0.0f) {
    SetWorldPosition(object, Vec3(pos.x, body->radius, pos.z));
    if (body->velocity.y < 0.0f) {
        body->velocity.y = -body->velocity.y * body->restitution;
        if (std::fabs(body->velocity.y) < 0.35f) body->velocity.y = 0.0f;
    }
    const float damping = (std::max)(0.0f, 1.0f - body->friction * 6.0f * (1.0f / 60.0f));
    body->velocity.x *= damping;
    body->velocity.z *= damping;
    body->grounded = true;
    ++m_stats.contacts;
}
```

这段顺序很重要：**先修正位置，再改速度**。如果只改速度不修位置，物体会停在地面以下；只修位置不改速度，下一帧还会继续往下钻。
### 4.4 冲量：碰撞响应的一般形式
对两个可动球 `a`、`b`，法线 `n` 从 `a` 指向 `b`，相对速度 `v_rel = v_b - v_a`，法向分量 `v_n = v_rel · n`。恢复系数 `e` 的定义是"分离速度 = `-e` × 接近速度"：
```
v_n' = -e · v_n
```

沿 `n` 施加冲量 `j`：`b` 得到 `+j`，`a` 得到 `-j`。速度变化是

```
Δv_n = j·(1/m_a + 1/m_b)
```

代入目标 `v_n' = -e·v_n`，解出

```
j = -(1 + e)·v_n / (1/m_a + 1/m_b)
v_a -= j·n/m_a
v_b += j·n/m_b
```

若 `b` 是静态物体（`m_b = ∞`，`1/m_b = 0`），分母只剩 `1/m_a`，等价于"只动 `a`"。

源码里球-球就是这样写的（**源码节选**，`PhysicsWorldSim.cpp:265-271`）：
```cpp
const Vec3  relative = b->velocity - a->velocity;
const float vn = Dot(relative, normal);
if (vn < 0.0f) {
    const float e = (std::min)(a->restitution, b->restitution);
    const float impulse = -(1.0f + e) * vn / invSum;
    a->velocity -= normal * (impulse * invA);
    b->velocity += normal * (impulse * invB);
}
```

`vn < 0` 表示还在接近；如果已经分离（`vn >= 0`），不再施加冲量，否则会把物体"吸"回来。

但本工程不是所有碰撞都走冲量：

| 碰撞对 | 响应方式 | 是否用质量 |
|---|---|---|
| 动态球 vs 动态球 | 法向冲量（上式） | 是 |
| 动态球 vs 静态盒 | 沿最近点法线反射速度 + 切向衰减 | 否（静态） |
| 动态盒 vs 静态盒 | 沿最小穿透轴反射该轴速度 | 否（静态） |
| 动态盒 vs 动态盒 | 不处理 | — |

所以"本工程用冲量法"只对球-球成立；球/盒对静态几何是简化的反射。**静态盒 vs 静态盒、动态盒 vs 动态盒都不会互相碰撞**，这也是它不能做堆箱子的原因之一。
### 4.5 摩擦：库仑模型 vs 这里的三行近似
真正的库仑摩擦限制切向冲量：
```
|j_t| ≤ μ·|j_n|
```

即"切向能拿走多少动量，最多是法向冲量的 μ 倍"；超过就滑动，不超过就粘住。本工程没有求 `j_n` 再夹紧，而是直接缩放切向速度：

| 场景 | 代码做法 | 后果 |
|---|---|---|
| 球落地 | `damping = max(0, 1 - friction*6/60)`，乘 `vx/vz` | `friction=1` 时仍保留 90% 切向速度，不是真摩擦 |
| 盒落地 | 硬编码 `vx *= 0.92; vz *= 0.92` | `friction` 字段对盒完全无效 |
| 球撞静态盒 | `v_t -= v_t * friction` | 等价于切向乘 `1-friction`，且每个求解迭代都做一次 |
| 盒撞静态盒 | 不做切向处理 | 没有摩擦 |

结论：这里的 `friction` 是**手感参数**，不是物理上的摩擦系数。斜坡上的静摩擦、滚动摩擦、不同材质的 μ 都不在这个模型里。
### 4.6 恢复系数与小速度截断
`restitution`（恢复系数）控制"弹回多少"：

- `e = 0`：完全非弹性，法向速度直接归零；
- `e = 1`：完全弹性，法向速度大小不变；
- 本工程默认 `0.45`，球的演示关卡设成 `0.6`。

代码在反弹后还有一行小速度截断：
```cpp
if (std::fabs(body->velocity.y) < 0.35f) body->velocity.y = 0.0f; // 球
if (std::fabs(body->velocity.y) < 0.5f)  body->velocity.y = 0.0f; // 盒
```

它的作用是让球在几次反弹后真正停住，而不是在毫米级高度上无限弹。注意：`e = 1` 时每次反弹速度不衰减，截断条件不会被触发，球会一直弹；本工程靠每步 0.98 的阻尼才让它最终慢下来。所以"`e = 1` 会永远弹"在**没有阻尼**时成立，在有阻尼时不一定。
### 4.7 休眠：代码写了，但默认参数下睡不着
当物体贴地且速度足够小，继续积分就是浪费。源码的判定是：
```cpp
const float speedSq = LengthSq(body->velocity);
if (body->grounded && speedSq < 0.02f) {
    body->sleepTimer += 1.0f / 60.0f;
    if (body->sleepTimer > 0.6f) body->velocity = Vec3(0, 0, 0);
} else {
    body->sleepTimer = 0.0f;
}
```
`Integrate` 里再判断一次 `grounded && sleepTimer > 0.6`，满足就跳过积分并给 `m_stats.sleeping` 加一。

按 `Solve` 的调用顺序推演，会得到一个反直觉的结果：

- 第 1 次 `ResolveGround`：球底 `bottom < 0`，位置被修正到 `y = r`，`grounded = true`，计时加 `1/60`；
- 第 2 次：`bottom` 正好等于 0，`bottom < 0` 为假，`else` 把 `grounded = false`，又因 `!grounded` 把 `sleepTimer` 清零；
- 第 3、4 次重复第 2 次。

所以一个贴地物体在每个 `Step` 结束时是 `grounded = false`、`sleepTimer = 0`，**只与 `y=0` 地面接触的根节点刚体（演示关卡都是）默认 `m_iterations = 4` 时休眠触发不了**，`m_stats.sleeping` 为 0。若把迭代次数改成 1，计时才会按每步 `1/60` 累积，约 0.6 秒后入睡。

另外，代码没有唤醒路径：休眠体在 `Integrate` 里被直接跳过，外部冲量虽然能在 `Solve` 里改速度，但下一帧又被清零；没有"被撞后 `sleepTimer = 0`"的分支，所以物体被撞/被推也不会自动唤醒。以上是按分支条件做的静态推演，本次未在 Windows 上运行验证。
## 5. 回到源码：谁调用谁

| 函数 | 位置 | 做什么 |
|---|---|---|
| `PhysicsWorld::Step` | `PhysicsWorldSim.cpp:77` | 清统计 → `Integrate` → `Solve` 重复 4 次 |
| `Integrate` | `:84` | 遍历所有刚体；跳过休眠；加重力、乘 0.98、更新位置 |
| `Solve` | `:111` | 先球-球，再逐体做地面和静态盒 |
| `ResolveGround` | `:125` | 地面反弹、摩擦、`grounded`、休眠计时 |
| `ResolveStaticBoxes` | `:170` | 对所有静态盒求交、推出、反射 |
| `ResolveSpherePairs` | `:225` | 动态球两两求交、冲量、累计位置修正 |
| `SphereVsBox` | `:18` | 球心到 AABB 最近点；球心在内部时选最小穿透轴 |
| `PhysicsWorld::RaySphere` | `:73` | 转调 `IntersectRaySphere`，当前无调用者 |

几个实现细节：

- `m_gravity` 默认 `-9.81`（`PhysicsWorld.h:43`），不是 `-22`；`-22` 是 `ThirdPersonController::gravity` 的默认值，两套系统互不相干。
- `m_iterations` 默认 `4`。它让多物体接触逐步收敛，也让 `contacts` 按每次 `Solve` 累加（最多约为实际接触的 4 倍）；同时后续迭代会把 `grounded` 清掉（见 4.7）。
- `ResolveStaticBoxes` 先把所有静态盒的推出量累加到局部变量 `position`，最后一次性写回，避免多个盒子互相覆盖修正。
- 物理统一在世界空间算；`SetWorldPosition` 在物体有父节点时用父矩阵的逆变换写回局部坐标。
- 没有宽相：每个动态体都要和所有静态盒比一遍，球-球是 `O(n²)`。
## 6. 数值走查：用源码的实际重力算 1 秒自由落体

下面的数值是按源码顺序离线递推，不是引擎日志。初始 `y = 0`、`v = 0`，`g = -9.81`，`h = 1/60`，并且**保留源码的 0.98 阻尼**。每步递推是：
```
v_{n+1} = (v_n + g·h) × 0.98
y_{n+1} = y_n + v_{n+1}·h
```

第一步手算：
```
v_1 = (0 - 9.81/60) × 0.98 = -0.1635 × 0.98 = -0.1602 m/s
y_1 = 0 + (-0.1602)/60 = -0.00267 m
```

继续算下去：

| 步数 | 时间 `t` | 速度 `v` | 高度 `y` |
|---|---|---|---|
| 1 | 0.017 s | -0.160 | -0.0027 |
| 2 | 0.033 s | -0.317 | -0.0080 |
| 10 | 0.167 s | -1.466 | -0.1384 |
| 30 | 0.500 s | -3.641 | -1.0320 |
| 60 | 1.000 s | -5.628 | -3.4156 |

对照三组结果：

| 算法 | 1 秒后 `y` | 1 秒后 `v` |
|---|---|---|
| 解析解 `½gt²` | -4.905 | -9.81 |
| 半隐式欧拉，**去掉** 0.98 阻尼 | -4.987 | -9.81 |
| 源码（半隐式 + 0.98 阻尼） | **-3.416** | **-5.628** |

差值主要不是积分器，而是那行 `velocity *= 0.98`：每步乘 0.98，60 步后速度只剩 `0.98^60 ≈ 0.30`。它把 1 秒自由落体从 4.9 米压到 3.4 米。如果你拿 `-4.905` 去验算代码，会以为重力或积分写错了；先检查这行阻尼。

去掉阻尼后，半隐式的结果是 `-4.987`，比解析解多掉约 8.2 cm，正好是 `½|g|h·t = ½×9.81×(1/60)×1`。这个误差随 `h` 线性减小，符合预期。

## 8. 实验

> 本环境是 Linux，不能运行 Windows 的 `ErMao.exe`；下面全部是**本次未实际运行**的条件性预期。

物理球在 `--level demo` 场景里（`World::CreateDemoScene`）：6 个动态球、5 个静态木箱。`--level thirdperson` 里只有静态盒和角色，没有动态刚体，不适合观察物理。

```bat
build\bin\ErMao.exe --level demo --play --frames 180
```

1. **看落地与弹跳**：球从不同高度落下，先落地再互相碰撞。预期弹跳一次比一次低；如果某个球一直在小高度抖，检查它的 `restitution` 是否接近 1、以及 0.35 的截断是否被触发。
2. **改恢复系数**：选中一个球，把 `restitution` 从 0.6 改成 0.8，重新运行。预期弹跳次数变多，但每步 0.98 阻尼和 0.35 截断仍会让它最终停住。
3. **改摩擦**：把球的 `friction` 调到 0，预期落地后水平速度不再被 `damping` 削减。要验证盒分支，先把一个木箱的 `isStatic` 取消（或新建动态盒）再让它落地；此时把 `friction` 调到 0，**预期它仍然很快停**，因为盒分支硬编码了 `0.92`，根本不读这个字段。
4. **看统计**：编辑器性能面板的文本是 `物理: 动态 %d / 静态 %d / 接触 %d`（`EditorUI.cpp:1180`），**没有"休眠"这一项**。在这个场景里预期是"动态 6 / 静态 5"，接触数随碰撞次数变化。
5. **改重力**：面板上的重力滑条改的是 `PhysicsWorld::m_gravity`，只影响刚体；它不会改第三人称控制器的 `gravity = -22`。
6. **改迭代次数**：把 `SolverIterations` 从 4 调到 1，预期球-球/球-盒的推出更软、`contacts` 统计变小，并且休眠计时才开始累积（默认 4 会在后续迭代把 `grounded` 清掉）。

如果球完全不动，排查顺序：`isStatic` 是否为 true、`useGravity` 是否为 false、是否处于编辑器暂停状态、场景是否真的加载了 `demo`。
## 9. 自测题

1. 写出半隐式欧拉的两步，并解释"先更新速度"为什么能改善往复系统的能量行为。**答案**：见 4.1；位置使用新速度，弹簧矩阵行列式为 1。
2. 本工程 1 秒自由落体为什么不是 `-4.905 m`？**答案**：见第 6 节；半隐式本身多掉约 8 cm，`velocity *= 0.98` 又把下落压到约 `-3.42 m`。
3. 从动量守恒和 `v_n' = -e·v_n` 推出冲量公式。**答案**：见 4.4；`j = -(1+e)v_n/(1/m_a+1/m_b)`。
4. 默认参数下休眠为什么触发不了？**答案**：见 4.7；第 1 次迭代修正位置后，后续迭代把 `grounded` 置 false 并清零计时。
5. 为什么两个动态木箱会互相穿过？**答案**：见 4.4 的表和 7；`ResolveSpherePairs` 只收集球，`ResolveStaticBoxes` 只处理静态盒，动态盒-盒没有分支。
## 练习（故意改坏）

1. 把 `Integrate` 里的两行顺序改成"先 `pos += velocity*dt`，再 `velocity.y += gravity*dt`"：**预期**自由落体在同一秒内掉得更少（显式欧拉），往复系统里振幅逐步变大；具体数值取决于 `h`，不是"必然爆炸"。
2. 删掉 `body->velocity *= (1.0f - 0.02f)`：**预期** 1 秒自由落体从约 `-3.42 m` 变回约 `-4.99 m`，弹跳高度也会变高；这行是"手感阻尼"，不是物理。
3. 把 `restitution` 改成 `1.2`：**预期**每次反弹速度变大，能量凭空增加；这不是物理上允许的恢复系数，只适合验证"代码确实按这个乘"。
4. 删掉 `if (std::fabs(velocity.y) < 0.35f)`：**预期**低恢复系数的球在毫米级高度上弹很久，直到 0.98 阻尼把它压下去。
5. 把 `m_iterations` 改成 `1`：**预期**多接触推出不充分、`contacts` 约为 1/4，但贴地物体反而可能开始休眠（见 4.7）。
