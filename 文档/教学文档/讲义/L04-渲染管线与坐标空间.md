## 1. 坐标空间链

```
模型空间 --(模型矩阵 M)--> 世界空间 --(视图矩阵 V)--> 相机空间 --(投影矩阵 P)--> 裁剪空间
        --(透视除法 /w)--> NDC --(视口变换)--> 屏幕像素
```

本工程矩阵约定（必须牢记，几乎每个 bug 都来自约定不一致）：

```
  CPU                          GPU
  ┌─────────────┐   M   ┌──────────┐   V   ┌──────────┐   P   ┌────────┐  /w  ┌─────┐  视口  ┌──────┐
  │ 模型顶点 p  │──────▶│ 世界空间 │──────▶│ 相机空间 │──────▶│ 裁剪空间│─────▶│ NDC │──────▶│ 像素 │
  └─────────────┘       └──────────┘       └──────────┘       └────────┘      └─────┘        └──────┘
        模型矩阵 M            视图矩阵 V          投影矩阵 P         透视除法      光栅化
```

- `Mat4` 按**列**存储：`m[col][row]`；
- 点/向量是**列向量**，变换写作 `p' = M · p`；
- 矩阵复合是**从右往左**：`MVP · p = (M · (V · (P · p)))`；
- 传给 HLSL 的 `column_major` 矩阵可以直接 `mul(M, p)`。

## 2. 视图矩阵

相机有位置 `eye`、单位正交基 `right`、`up`、`forward`（看向 `-Z`）。
视图矩阵把世界点变到相机空间：

```
x_cam = right · (p - eye)
y_cam = up    · (p - eye)
z_cam = -forward · (p - eye)      // 相机看向 -Z，所以前方点的 z 为负
```

矩阵形式：

```
      | right.x  right.y  right.z  -right·eye |
V =   | up.x     up.y     up.z     -up·eye    |
      | -f.x     -f.y     -f.z     f·eye      |
      | 0        0        0        1          |
```

实现上不显式求逆：直接由相机基构造（`Camera::View()`），因为相机基是正交的，
`V` = 旋转部分的转置 + 平移项，这正是 `R^T · T(-eye)` 的展开。

## 3. 透视投影矩阵（D3D 约定，深度映射到 [0,1]）

本工程用右手系、相机看向 `-Z`、深度范围 `[0,1]`（D3D）。设视场角 `fovY`、宽高比 `a`、近远平面 `n, f`。

**目标**：

- 相机空间的 `x, y` 除以 `-z` 得到 NDC（透视除法由 GPU 的 `/w` 完成，所以把 `-z` 写进 `w`）；
- `z = -n → ndc_z = 0`，`z = -f → ndc_z = 1`。

构造：

```
y_clip = (1/tan(fovY/2)) · y_cam
x_clip = y_clip / a
w_clip = -z_cam
z_clip = Q · z_cam + B
```

要求 `z_clip/w_clip` 在 `z=-n` 时为 0、`z=-f` 时为 1：

```
(Q·(-n) + B) / n = 0   →  B = Q·n
(Q·(-f) + B) / f = 1   →  Q·(n - f) = f  →  Q = f/(n-f),  B = nf/(n-f)
```

对应代码：

```cpp
r.m[0][0] = x;                        // 1/(a·tan)
r.m[1][1] = y;                        // 1/tan
r.m[2][2] = farZ / (nearZ - farZ);    // Q
r.m[2][3] = -1.0f;                    // w = -z
r.m[3][2] = nearZ * farZ / (nearZ - farZ); // B
```

**深度非线性**：`ndc_z = (Q z + B)/(-z) = -Q - B/z`，对 `z` 是双曲线。
靠近近平面精度高、远处精度低——这就是"深度冲突（z-fighting）多发生在远处"的数学原因。
缓解手段：提高近平面、反向 Z（reversed-Z，本工程未做）。

## 4. 视锥剔除

### 4.1 从 viewProj 提取 6 个平面（Gribb-Hartmann）

设 `M = P·V`，行向量记 `r0..r3`。裁剪空间条件是：

```
-w ≤ x ≤ w,  -w ≤ y ≤ w,  0 ≤ z ≤ w      （D3D）
```

以左平面 `x ≥ -w` 为例，即 `(r3 + r0)·p ≥ 0`，所以平面系数就是 `r3 + r0`。
同理：

| 平面 | 系数 |
|---|---|
| 左 | r3 + r0 |
| 右 | r3 - r0 |
| 下 | r3 + r1 |
| 上 | r3 - r1 |
| 近 | r2（因为 z ≥ 0） |
| 远 | r3 - r2 |

代码（`Frustum::FromViewProj`）与此一一对应。

### 4.2 AABB vs 平面

平面 `n·p + d ≥ 0` 为内侧。对 AABB，沿法线取"最远点"（p-vertex）：

```
p = (n.x ≥ 0 ? max.x : min.x, n.y ≥ 0 ? max.y : min.y, n.z ≥ 0 ? max.z : min.z)
```

若 `p` 都在平面负侧，整个盒子在外部 → 剔除。这是**保守**测试：
盒子可能被判为相交但实际不可见，但绝不会错误剔除。

### 4.3 收益

本工程在 `BuildBatches` 里用 `JobSystem::ParallelFor` 并行算可见性，
统计面板的"剔除"就是被剔除的 item 数。

## 5. 实例化与法线矩阵

### 5.1 为什么要实例化

1000 个相同网格：逐物体 `Draw` = 1000 次状态切换 + 1000 次 draw；
实例化 = 1 次 draw + 1000 份实例数据。CPU 提交时间从 O(n) 的状态切换降到 O(1)。

实例数据 144 字节：世界矩阵 4 列（64B）+ 法线矩阵 3 列（48B）+ albedo（16B）+ 参数（16B）。

### 5.2 法线矩阵 = 逆转置

法线是**余切向量**，在非均匀缩放下不能直接用模型矩阵变换。
设切线 `t`、法线 `n`，`n·t = 0`。变换后要求 `n'·t' = 0`：

```
t' = M t
n' = (M^{-1})^T n
证明：n'·t' = ((M^{-1})^T n)·(M t) = n^T M^{-1} M t = n·t = 0
```

所以顶点数据里存 `(M^{-1})^T`（3×3 足够，法线只关心方向）。
HLSL 里用"列拼成行向量"的技巧复现这个乘法（见 `PBR.hlsl` 的 `ApplyWorldDir`），
审核报告 R5 曾逐项验算过这个约定链，结论是等价的。

---

### 5.3 数值演算：非均匀缩放下的法线

设 `M = diag(2, 1, 1)`（x 方向拉长一倍），表面法线 `n = (0, 1, 0)`，切线 `t = (1, 0, 0)`。

直接用 M 变换法线：`M·n = (0,1,0)`——看起来没变；
但切线 `M·t = (2,0,0)`，与 `(0,1,0)` 仍然垂直，这个例子看不出问题。

换一个斜面：`n = (1, 1, 0)/√2`，`t = (1, -1, 0)/√2`。
直接变换：`M·n = (2, 1, 0)`（未归一化），`M·t = (2, -1, 0)`；
点积 `4 - 1 = 3 ≠ 0` —— **不再垂直**，说明法线变了形。

正确做法：`(M⁻¹)ᵀ = diag(0.5, 1, 1)`，
`(M⁻¹)ᵀ·n = (0.5, 1, 0)`；点积 `(0.5,1,0)·(2,-1,0) = 1 - 1 = 0` ✓。

这就是"法线矩阵必须用逆转置"的最小反例。

### 数值演算（跟一遍）

相机 `eye=(0,0,5)`，看向 `-Z`，`fovY=60°`，`aspect=16/9`，点 `p=(1,0,-2)`。

```
view 后：p_cam = (1, 0, -7)          // 相机在 z=5，p 在 z=-2，距离 7
tan(30°) = 0.5774 → y_scale = 1.7321, x_scale = 0.9743
x_clip = 0.9743
y_clip = 0
z_clip = Q·(-7) + B,  Q = f/(n-f), B = nf/(n-f)
w_clip = 7
ndc = (0.1392, 0, z_clip/7)
屏幕：x = (ndc.x*0.5+0.5)*width
```

代入 `n=0.1, f=100`：`Q = 100/99.9 = 1.001`，`B = 10/99.9 = 0.1001`，
`z_clip = -7.007 + 0.100 = -6.907`，`ndc.z = -0.987`——**负数说明这个点在近平面之外（相机背后）**，
所以会被裁掉。把 `p` 换成 `(1,0,-12)`（相机前方 17m）再算一次，`ndc.z` 就是正的。
