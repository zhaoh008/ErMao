## 0. 本讲地图

- **现象/最简实现**：立方体最后变成屏幕上一块有透视的像素；先把顶点乘一个矩阵，再除以 `w`。
- **它怎样坏/正式方案**：没有相机/投影/裁剪，矩阵顺序写反，`w<=0` 被当正常点；正式方案是

- **源码核对与例子**：`Camera::View/Projection/ViewProjection`、`Mat4::Perspective`、`Frustum::FromViewProj`、

## 1. 先看现象：立方体怎样变成屏幕像素

一个立方体的顶点在**模型空间**，例如 `(-0.5,-0.5,-0.5)` 到 `(0.5,0.5,0.5)`。屏幕像素是二维的、左上角为原点。
中间要回答四个问题：物体摆在哪/多大/朝向（`M`）、相机在哪/朝哪（`V`）、透视怎么来（`P`）、
视锥外的东西怎么不画（裁剪与视锥剔除）。

---

## 2. 最简实现：一个矩阵 + 除以 w

先不管 M/V/P 的区分，假设已经有一个 4×4 矩阵 `M` 把顶点变到**裁剪空间**。GPU 的顶点着色器输出
`SV_POSITION` 就是裁剪空间坐标，之后硬件做透视除法并光栅化：

**概念伪代码：最小顶点变换 + 视口映射**

```cpp
Vec4 clip = M * Vec4(p_local, 1.0f);
if (clip.w <= 0.0f) return;              // 相机背后，别当正常点
Vec3 ndc = clip.xyz / clip.w;             // 透视除法
int px = int((ndc.x * 0.5f + 0.5f) * width);
int py = int((0.5f - ndc.y * 0.5f) * height);  // 屏幕 y 向下
```

这段能画出东西，但立刻暴露三个问题：`M` 若只是模型矩阵，顶点仍在世界空间、`w=1`，没有透视；
相机移动画面不动（没有 `V`）；`w<=0` 的点直接除会得到翻转坐标（没有裁剪）。

## 3. 拆成三个矩阵：M、V、P

### 3.1 坐标空间链

**示意：坐标空间链**

```
模型空间 --M--> 世界空间 --V--> 相机空间 --P--> 裁剪空间 --/w--> NDC（归一化设备坐标） --视口--> 屏幕像素
```

本工程的约定（`core/Math.h` 顶部注释，必须牢记）：

- `Mat4` 按**列**存储 `m[col][row]`，与 HLSL `float4x4` 的 `column_major` 一致；点是**列向量**，`p'=M·p`；
- `C=A*B` 表示“先 B 后 A”；右手系，相机看 `-Z`，深度 `[0,1]`（D3D）。

因此正确的复合顺序只有一种：

```
p_clip = P · V · M · p_local
```

从右往左：先 M，再 V，最后 P。**一个常见错误是把 P 放到最右边**：等于用投影矩阵乘世界点，再把结果当相机空间继续变换，几何意义完全错。判断顺序看“每一步的输入/输出空间是否衔接”，不要背字母顺序。

### 3.2 真实代码

**源码节选（缩短）：`renderer/Camera.h`**

```cpp
Mat4 View() const { return Mat4::LookAt(position, position + Forward(), up); }
Mat4 Projection() const {
    if (orthographic) { ... return Mat4::Orthographic(-w, w, -h, h, nearZ, farZ); }
    return Mat4::Perspective(fovY, aspect, nearZ, farZ);
}
Mat4 ViewProjection() const { return Projection() * View(); }
```

**源码节选：`shaders/PBR.hlsl`**

```hlsl
float4 worldPos = ApplyWorld(float4(input.position, 1.0), input.col0, input.col1, input.col2, input.col3);
o.clip = mul(gViewProj, worldPos);
```

`ApplyWorld` 用 4 个“列”拼矩阵并 `mul(p,W)`，等价 `M·p`；`gViewProj=P·V`，`mul(gViewProj,worldPos)`
等价 `(P·V)·(M·p)`，合起来就是 `P·V·M·p`。

## 4. 视图矩阵：把世界搬到相机眼前

相机有位置 `eye`、单位正交基 `right/up/forward`，看向 `-Z`。世界点 `p` 变到相机空间：

```
x_cam = right · (p - eye)
y_cam = up    · (p - eye)
z_cam = zaxis · (p - eye)      // zaxis = -forward，所以前方点的 z_cam 为负
```

`Camera::View()` 调用 `Mat4::LookAt(position, position + Forward(), up)`。`LookAt` 里（**源码节选**）：

```cpp
const Vec3 zaxis = Normalize(eye - target);   // 相机 +Z 指向后方
const Vec3 xaxis = Normalize(Cross(up, zaxis));
const Vec3 yaxis = Cross(zaxis, xaxis);
// 行：xaxis, yaxis, zaxis；平移项：-dot(axis, eye)
```

因为基正交，`V` 的旋转部分就是基向量的转置，平移项是 `-R^T·eye`，不需要通用求逆。

**数值例子**：`eye=(0,0,5)`、看向 `-Z`、`up=(0,1,0)` 时 `zaxis=(0,0,1)`、`xaxis=(1,0,0)`、`yaxis=(0,1,0)`；
点 `p=(1,0,-2)` 变为 `p_cam=(1,0,-7)`。前方点的 `z_cam` 是负数。

## 5. 透视投影：为什么 `Q` 和 `B` 都是负数

### 5.1 目标

相机空间的 `x,y` 要除以 `-z` 才能“近大远小”；GPU 的透视除法固定除以 `w`，所以把 `-z_cam` 写进 `w`。
深度要满足：`z_cam=-n → ndc.z=0`，`z_cam=-f → ndc.z=1`（D3D）。

构造：

```
y_clip = (1/tan(fovY/2)) · y_cam
x_clip = y_clip / aspect
w_clip = -z_cam
z_clip = Q · z_cam + B
```

令 `d=-z_cam>0`，则 `z_clip=-Q d+B`，`w=d`。代入两个边界：

```
d=n: (-Q n + B)/n = 0  →  B = Q n
d=f: (-Q f + B)/f = 1  →  Q(n-f) = f  →  Q = f/(n-f),  B = nf/(n-f)
```

因为 `n<f`，**`Q` 和 `B` 都是负数**。这是本工程最容易写错符号的地方：

- 若把两者都写成 `Q=f/(f-n)`、`B=nf/(f-n)`（正数），近平面仍是 0，但远平面映射到 `-1`，深度范围变成 `[0,-1]`；
- 若只把 `B` 的符号写反（`Q=f/(n-f)` 为负、`B=nf/(f-n)` 为正），近平面不再是 0、远平面也不再是 1，两个边界都失败。

**源码节选：`core/Math.h` 的 `Mat4::Perspective`**

```cpp
const float y = 1.0f / std::tan(fovYRad * 0.5f);
const float x = y / aspect;
r.m[0][0] = x;
r.m[1][1] = y;
r.m[2][2] = farZ / (nearZ - farZ);            // Q，负数
r.m[2][3] = -1.0f;                             // w = -z
r.m[3][2] = nearZ * farZ / (nearZ - farZ);     // B，负数
```

`m[2][3]=-1` 在列主序里是“第 2 列第 3 行”，也就是 `w` 行的 z 系数，所以 `w_clip=-z_cam`。

### 5.2 深度非线性

把 `z_cam=-d` 代入：

```
ndc.z = (Q·(-d)+B)/d = -Q + B/d = f/(f-n) · (1 - n/d)
```

对 `d` 是双曲线。以 `n=0.1, f=100` 为例：`d=0.1→0`、`0.2→0.5005`、`1→0.9009`、`10→0.991`、`100→1`。
前 10 cm 就用掉一半深度范围，远处 90 m 只占不到 1%——这就是“深度冲突多发生在远处”的原因。
把近平面从 0.1 提到 1.0，`ndc.z = 100/99·(1-1/d)`，分布会均匀一些（`d=2 → 0.505`，`d=10 → 0.909`）。
本工程用常规 Z（不是 reversed-Z），深度格式 `D24_UNORM_S8_UINT`；反向 Z 会更进一步改善远处精度，但未实现。

## 6. 裁剪空间与 `w` 的符号

D3D 的裁剪条件是（`w>0` 的前提下）：

```
-w ≤ x ≤ w,  -w ≤ y ≤ w,  0 ≤ z ≤ w
```

硬件会裁剪跨越平面的三角形（逐顶点，不是“剔除整个物体”）。`w<=0` 表示点在相机平面之后，不能直接拿
`ndc=clip/w` 当正常坐标——除以负数会翻转 x/y/z 的符号。

`Camera::WorldToScreen` 明确检查了这一点（**源码节选**，合并了赋值）：

```cpp
const Vec4 clip = ViewProjection() * Vec4(world, 1.0f);
if (clip.w <= 1e-5f) return false;   // 在相机背面
outScreen = Vec2((clip.x/clip.w * 0.5f + 0.5f) * screenSize.x,
                 (0.5f - clip.y/clip.w * 0.5f) * screenSize.y);
```

这也解释了为什么天空/后处理的全屏三角形可以写 `z=1`：它们用 `SetDepthNone`，不参与深度比较；
普通不透明物体在 `LESS` 下写 `z=1` 会和清深度的 1.0 比较失败而被丢弃（第 0 课也提到）。

## 7. 视锥剔除：从 `P·V` 提取 6 个平面

设 `VP=P·V`，把 `VP` 的 4 个**行**记为 `r0..r3`（列主序下 `row(r)=(vp.m[0][r],vp.m[1][r],vp.m[2][r],vp.m[3][r])`）。
裁剪条件是 `-w≤x≤w` 等；以左平面 `x≥-w` 为例，即 `(r3+r0)·p≥0`，所以平面系数是 `r3+r0`：

| 平面 | 系数 | 平面 | 系数 |
|---|---|---|---|
| 左 | `r3+r0` | 右 | `r3-r0` |
| 下 | `r3+r1` | 上 | `r3-r1` |
| 近 | `r2`（`z≥0`） | 远 | `r3-r2` |

**源码节选（缩短）：`core/Math.h` 的 `Frustum::FromViewProj`**

```cpp
auto row = [&](int r) { return Vec4(vp.m[0][r], vp.m[1][r], vp.m[2][r], vp.m[3][r]); };
const Vec4 r0 = row(0), r1 = row(1), r2 = row(2), r3 = row(3);
f.planes[0] = makePlane(r3 + r0); // left
f.planes[4] = makePlane(r2);      // near (z >= 0)
f.planes[5] = makePlane(r3 - r2); // far
// right = r3-r0, bottom = r3+r1, top = r3-r1
```

`makePlane` 会归一化法线和 `d`；`DistanceTo(p)=dot(n,p)+d`，`>=0` 为内侧。

**AABB（轴对齐包围盒）测试**：沿平面法线取最远点（p-vertex）`p=(n.x>=0?max.x:min.x, ...)`；若连它都在负侧，整个盒子在外。
这是**保守**测试：可能有假阳性（整体在视锥外但未被任一平面单独判负），但不会错误剔除。

**源码节选（缩短）：`Renderer::BuildBatches`（省略角点循环与 `world` 声明）**

```cpp
const Frustum frustum = camera.GetFrustum();
m_visibility.assign(itemCount, 1);
if (cull) JobSystem::ParallelFor(0, itemCount, [&](u32 i) {
    // 8 个局部角点经 item.world 变换，取世界 AABB
    m_visibility[i] = frustum.IntersectsAABB(world) ? 1 : 0;
}, 128);
for (u32 i = 0; i < itemCount; ++i) if (!m_visibility[i]) ++m_stats.culled;
```

真实细节：`cull` 是 `!GpuCullEnabled()`，GPU 剔除开启时 `BuildBatches` 不做 CPU 剔除、`culled` 为 0，
剔除交给 `Cull.hlsl`（第 22 讲），统计在 `gpuVisibleInstances`；CPU 剔除路径下无效网格也会被置 0，所以 `culled`
不只是“视锥剔除数”；世界 AABB 由 8 角点变换后取 min/max，对旋转物体偏松（保守）；排序按 `(mesh Id, texture Id)`。

## 8. 数值例子：相机前方与相机背后的点

相机 `eye=(0,0,5)`，看向 `-Z`，`fovY=60°`，`aspect=16/9`，`n=0.1`，`f=100`。

```
y_scale=1/tan(30°)=1.732051；x_scale=y_scale/(16/9)=0.974279
Q=100/(0.1-100)=-1.001001；B=10/(0.1-100)=-0.100100
```

### 8.1 相机前方：`p=(1,0,-2)`

| 步骤 | 计算 | 结果 |
|---|---|---|
| 视图 | `p_cam` | `(1,0,-7)` |
| 投影 | `x_clip=0.974279`，`z_clip=Q·(-7)+B=6.906907`，`w=7` | — |
| 透视除法 | `z: 6.906907/7`，`x: 0.974279/7` | **`ndc.z=0.986701`**，`ndc.x=0.139183` |
| 屏幕（1920×1080） | `(0.139183*0.5+0.5)*1920` | `px≈1093.6`，`py=540` |

结论：`w=7>0`，`0≤ndc.z≤1`，点在前方、接近远平面，**可见**。**常见错误**：若写成 `Q=f/(f-n)=+1.001001`、
`B=nf/(f-n)=+0.100100`，会得到 `z_clip=-6.906907`、`ndc.z=-0.986701`，误判“在相机背后”；错在分母用 `f-n` 而非 `n-f`。
真正的相机背后点是 `w<0`，不是“ndc.z 为负”。

### 8.2 相机背后：`p=(1,0,8)`

| 步骤 | 计算 | 结果 |
|---|---|---|
| 视图 | `p_cam` | `(1,0,3)`（z 比 eye 大，在背后） |
| w / 投影 z | `w=-z_cam`；`z_clip=Q·3+B` | **`w=-3`**，`z_clip=-3.103103` |
| 若硬除 | `z_clip/w` | `ndc.z≈1.034`（无意义） |

结论：`w=-3<0`，裁剪条件 `0≤z≤w` 不成立，**被裁剪**；不要用 `ndc.z>1` 判断“远平面外”，`w<0` 时 NDC 已被符号翻转。

### 8.3 近/远平面边界

`p=(1,0,4.95)`：`d=0.05`、`w=0.05`、`z_clip=-0.05005`、`ndc.z≈-1.001` → `z<0`，近平面裁掉；
`p=(1,0,-200)`：`d=205`、`w=205`、`z_clip=205.105`、`ndc.z≈1.0005` → `z>w`，远平面裁掉。

## 9. 实例化与法线矩阵（与本讲矩阵约定相关）

`BuildBatches` 为每个可见物体填 144 B 的 `InstanceVertex`：世界矩阵 4 列（64）+ 法线矩阵 3 列（48）
+ albedo（16）+ 参数（16）；`DrawBatches` 用一次 `DrawIndexedInstanced` 画同网格同贴图的一批物体。
法线是**余切向量**，非均匀缩放下不能直接用 `M`：

`t'=M·t`，`n'=(M^{-1})^T·n`；证明 `n'·t'=((M^{-1})^T n)·(M t)=n^T M^{-1} M t=n·t=0`。

真实代码在 `Renderer::BuildBatches` 里 `item.world.Inverse().Transposed()` 填 `nrm0..nrm2`，`PBR.hlsl` 用
`mul(float4(n,0), NM)` 复现。反例：`M=diag(2,1,1)`，`n=(1,1,0)/√2`、`t=(1,-1,0)/√2`，直接变换点积 `3≠0`；
用 `(M^{-1})^T=diag(0.5,1,1)` 后 `(0.5,1,0)·(2,-1,0)=0`。

## 12. 自测题

1. 推导 `z_clip` 的两个边界条件，验证 `Q=f/(n-f)`、`B=nf/(n-f)`。答案见 §5.1。
2. 近平面从 0.1 提到 1.0，深度精度如何变化？答案：`ndc.z=f/(f-n)(1-n/d)`；n 增大后近处不再吃掉大部分 [0,1]，远处相对改善，但近处裁掉更多。
3. 验证 `(M^{-1})^T` 与 `M` 对法线的差别。答案：`M=diag(2,1)`，`n=(1,1)`、`t=(1,-1)`；`M n=(2,1)` 与 `M t=(2,-1)` 点积 3，`(M^{-1})^T n=(0.5,1)` 点积 0。
4. 为什么 p-vertex 测试保守？答案：只检查“是否整个盒子在某平面负侧”；不满足时仍可能整体在视锥外，所以有假阳性、无假阴性。
5. 相机背后的点 `ndc.z` 一定大于 1 吗？答案：不一定；`w<0` 时除法符号翻转，NDC 无正常意义，先看 `w`（§8.2）。
