## 1. 现象：敌人为什么绕开箱子

第三人称关卡里有三个红色巡逻者，场地里有台阶、平台、立柱。玩家躲到立柱后面，巡逻者会绕过立柱追过来，而不是顶着柱子原地抖。

这件事拆开是三个问题：

1. **哪里能走？** 把 3D 场地压成一张"可行走 / 阻挡"的平面地图；
2. **怎么走最近？** 在这张图上找一条从当前位置到玩家的格子序列；
3. **什么时候走？** 看见玩家才追，否则巡逻——这是感知和状态决定的。

先给一个最朴素的实现，看它怎样卡住。

---

## 2. 最简实现：朝玩家直线走 + 撞墙滑动

**概念伪代码**（不是 `NavAgent` 的代码）：

```cpp
void Chase(Enemy& e, const Player& p, float dt) {
    Vec3 dir = Normalize(p.position - e.position);
    dir.y = 0.0f;
    e.position += dir * e.speed * dt;

    // 与静态盒求最近点，把自己推到盒子表面外 radius 处
    for (const AABB& box : staticBoxes) {
        Vec3 closest = ClampPoint(e.position, box);
        Vec3 diff = e.position - closest;   // y 置 0
        float d = Length(diff);
        if (d < e.radius && d > 1e-4f)
            e.position += diff / d * (e.radius - d);
    }
}
```

这个思路在游戏里很常见：**移动 + 推离（penetration resolution）**，也叫"撞墙滑动"。如果只想让敌人沿墙滑、不要穿墙，它已经够用。本仓库的 `game/WaveGame.cpp` 里有一个同类实现：`MoveWithSlide`（刷怪 Demo 的敌人用它直线追玩家，见 `EnemyComponent::MoveToward`）。

## 3. 它具体在哪里失败

### 3.1 墙在正前方时，滑动没有"绕"的分量

设敌人在 `(0, 0)`，玩家在 `(6, 0)`，中间一堵静态盒 `x ∈ [2, 2.5]`、`z ∈ [-1, 3]`。敌人每帧的方向都是 `(+1, 0)`：

- 推到盒子表面外后，敌人停在 `x ≈ 2 - 0.42 = 1.58`；
- 下一帧方向仍然是 `(+1, 0)`，推离又把 `x` 推回 `1.58`；
- 敌人的 `z` 从来没有变化，所以它永远找不到 `z > 3` 或 `z < -1` 的绕行路线。

结果是"贴着墙原地踏步"，玩家在墙后安然无恙。这不是数值问题，加再大的速度也没用。

### 3.2 凹形障碍会让两个推离方向互相抵消

L 形或 U 形障碍里，敌人同时被两面墙推，合力指向缺口之外；它会在角落里抖动或停住。只靠"最近点推离"没有任何"全局该往哪走"的信息。

### 3.3 局部最优

直线追击每一步都让"到玩家的直线距离"变小，但这是一条**局部**规则。墙后需要先远离玩家、绕过去再接近——直线距离会短暂变大，直线追击永远不会做这种"先变差再变好"的决定。

### 3.4 没有"可走区域"的概念

推离只处理"已经撞上的盒子"。它不知道场地边界在哪、哪个缝隙比角色宽、哪些区域根本走不进去，所以也没法保证"存在一条路"。

## 4. 正式方案：栅格 + A\* + 感知

### 4.1 导航栅格（NavGrid）

一句话：把 XZ 平面切成正方形格子，每格标记"可走 / 阻挡"，把连续空间变成图。

本工程的构建参数（`World::RebuildNavigation`，**源码节选**）：

```cpp
m_navGrid.Build(*this, -25.0f, 25.0f, -25.0f, 25.0f, 0.5f, 0.45f);
```

即 X/Z 各 `[-25, 25)`、格子边长 `0.5 m`、角色半径 `0.45 m`，得到 `100 × 100` 格；日志打印：

```text
导航网格生成：100 x 100 格（0.50 m/格）
```

构建步骤（`NavGrid::Build` → `RasterizeBoxes`）：

1. 遍历所有 `GameObject`，只处理带 `RigidBodyComponent` 且 `isStatic == true` 的对象；
2. 取它的世界位置和 `halfExtents`，在 XZ 上各加 `agentRadius`，得到一个"膨胀后的盒子"；
3. 把这个盒子覆盖的格子全部标成阻挡（`m_blocked[index] = 1`，`index = z * W + x`）；
4. 最后把地图最外一圈格子也标成阻挡，防止路径走出边界。

```cpp
// 概念伪代码
cellX = int((worldX - originX) / cellSize);
cellZ = int((worldZ - originZ) / cellSize);
index = cellZ * width + cellX;
```

注意"膨胀"不是"把阻挡格向外扩 N 格"，而是**先把每个静态盒的 XZ 尺寸放大 `agentRadius`，再整体光栅化**——效果相近，但实现更直接。角色半径 0.45 m、格子 0.5 m，于是每个盒子大约向四周多覆盖 1 格。

### 4.2 A\*：在格子上找最短路

三个量：

- `g(n)`：从起点走到 `n` 的**实际**代价；
- `h(n)`：从 `n` 到终点的**估计**代价（启发式）；
- `f(n) = g(n) + h(n)`：优先队列的排序键。

每次弹出 `f` 最小的格子；如果是终点就结束；否则把 8 个邻居中可走的格子按 `g' = g + step` 更新。`step` 是 1（上下左右）或 `√2`（对角）。

本工程的启发式是**八方向距离（octile distance）**，不是曼哈顿距离：

**源码节选：`NavGrid::FindPath` 的启发式**

```cpp
const float dx = std::abs(x - goalX);
const float dz = std::abs(z - goalZ);
return (dx + dz) + (1.41421356f - 2.0f) * std::min(dx, dz);
```

化简就是 `max(dx,dz) + (√2−1)·min(dx,dz)`：先沿对角线走 `min` 步（每步 `√2`），再沿直线走 `|dx−dz|` 步（每步 1）。它正好等于八邻接下的最短距离，因此**可采纳**（不会高估剩余代价）。

两个实现细节：

- **8 邻接**：`offsets[8][2]` 含四个对角方向；对角移动前后要检查两个正交邻格都可走，禁止"贴角穿越"；
- **目标在障碍里**：`FindPath` 会在半径 1~4 的方形邻域里找一个可走格替代；**起点在障碍里**则直接返回 `false`，不做穿墙兜底。

### 4.3 路径平滑

A\* 给的是格子中心序列，直接走会像"楼梯"。`NavGrid::SmoothPath` 做**视线拉直（string pulling）**：

```text
从当前点 i 开始，尽量找最远的 j，使得 i 到 j 的连线不穿过阻挡；
把 j 加入结果，令 i = j，重复。
```

`LineOfSight` 的判定是：沿 `a→b` 每 `cellSize * 0.5`（0.25 m）采样一次，每个采样点都必须落在可走格内。所以平滑只保证"采样点可走"，不保证角色半径。

### 4.4 感知：距离 + 视野锥 + 遮挡

`NavAgentComponent::CanSeePlayer` 三个条件缺一不可：

**源码节选：`NavAgentComponent::CanSeePlayer`**

```cpp
if (distance > sightRange || distance < 0.001f) return false;
const Vec3 dir = toPlayer / distance;
const Vec3 forward = Normalize(m_owner->Forward());
const float cosAngle = Dot(forward, dir);
if (cosAngle < std::cos(ToRadians(sightAngleDegrees))) return false;
if (world->Nav().IsValid()) {
    if (!world->Nav().HasLineOfSight(eye, playerPos)) return false;
}
return true;
```

- **距离**：默认 `sightRange = 13 m`；演示/第三人称关卡把它设成 12；
- **夹角**：`sightAngleDegrees` 默认 75，代码里是拿它当**半角**用（比较 `cos(75°)`），所以总视野张角是 **150°**。字段名叫"视野角"，但语义是半角，这一点很容易配错；
- **遮挡**：用导航栅格做 2D 视线检测。它只看 XZ，不看高度，所以矮台阶、高架长廊都会挡视线。

只做距离会"隔墙追人"；只做夹角会"背后长眼"；三个都做才像"看见"。

### 4.5 状态：本工程只有两态，而且每帧重算

`NavAgentComponent` 的 `state` 只有 `0=巡逻`、`1=追击`，并且每帧直接由感知结果赋值（**源码节选**）：

```cpp
Vec3 playerPos;
const bool seesPlayer = CanSeePlayer(world, playerPos);
state = seesPlayer ? 1 : 0;
```

所以它**不是**带记忆的状态机：没有"丢失目标后继续追 2 秒"之类的过渡，`state` 只是"这一帧看不看得见"的投影。行为差异由移动逻辑体现：

- 看得见：每 `repathInterval = 0.6 s` 重新向玩家寻路；速度是 `moveSpeed × 1.35`，离玩家小于 2.5 m 时降到 `moveSpeed × 0.2`；
- 看不见：路径走完后等 `0.5~1.8 s`，在 `patrolCenter` 周围 `patrolRadius`（默认 7 m）内随机取点，重新寻路（间隔 1.2 s）。

路径点推进阈值是 `0.35 m`；转向用 `turnSpeed`（默认 8 rad/s）限制每帧角度，而不是瞬间转向。

## 6. 一个 5×5 的手算例子

下面是一个**手算用的抽象 5×5 栅格**（不是本工程的 100×100，省略边界环）。`S=(0,4)` 是起点，`G=(4,0)` 是终点，`#` 是阻挡，坐标写作 `(x,z)`：

```text
z=0   .  .  #  .  G
z=1   .  #  #  .  .
z=2   .  .  #  .  .
z=3   .  .  .  .  .
z=4   S  .  #  .  .
        x=0 x=1 x=2 x=3 x=4
```

阻挡格：`(2,0) (1,1) (2,1) (2,2) (2,4)`。八邻接、对角代价 `√2`、禁止贴角穿越，启发式用上面的 octile 公式。

先验算两个 `h`：

- `S(0,4)` 到 `G(4,0)`：`dx=4, dz=4`，`h = max(4,4) + 0.4142 × min(4,4) = 4 + 1.657 = 5.657`；
- `(2,3)` 到 `G`：`dx=2, dz=3`，`h = 3 + 0.4142 × 2 = 3.828`。

A\* 的弹出顺序（下表是其中一种合法顺序；`f` 相同时 `std::priority_queue` 不保证顺序，平局只影响走法，不影响最优代价）：

| 弹出的格子 | `g` | `h` | `f = g+h` |
|---|---|---|---|
| `(0,4)` S | 0.000 | 5.657 | 5.657 |
| `(1,3)` | 1.414 | 4.243 | 5.657 |
| `(1,4)` | 1.000 | 5.243 | 6.243 |
| `(0,3)` | 1.000 | 5.243 | 6.243 |
| `(2,3)` | 2.414 | 3.828 | 6.243 |
| `(1,2)` | 2.414 | 3.828 | 6.243 |
| `(3,3)` | 3.414 | 3.414 | 6.828 |
| `(3,2)` | 4.414 | 2.414 | 6.828 |
| `(4,2)` | 4.828 | 2.000 | 6.828 |
| `(3,1)` | 5.414 | 1.414 | 6.828 |
| `(4,1)` | 5.828 | 1.000 | 6.828 |
| `(4,0)` G | 6.828 | 0.000 | 6.828 |

`g` 的验算：`(0,4)→(1,3)` 是对角，`1.414`；`→(2,3)` 是直走，`2.414`；`→(3,3)` 直走，`3.414`；`→(3,2)` 直走，`4.414`；`→(3,1)` 直走，`5.414`；`→(4,0)` 对角，`6.828`。最终路径：

```text
(0,4) → (1,3) → (2,3) → (3,3) → (3,2) → (3,1) → (4,0)
代价 = 1.414 + 1 + 1 + 1 + 1 + 1.414 = 6.828
```

注意从 `(2,3)` 不能直接对角走到 `(3,2)`：对角移动要求两个正交邻格 `(3,3)` 和 `(2,2)` 都可走，而 `(2,2)` 是阻挡。这条限制让路径先直走到 `(3,3)` 再往下，绕开了 `(2,2)`。

如果改用曼哈顿距离做启发式（8 邻接），`h` 会高估对角代价，`(4,0)` 可能先被别的格子挤出队列，路径不再保证最优；这就是"启发式必须可采纳"的具体含义。若启发式恒为 0，A\* 退化成 Dijkstra，仍然正确，只是扩展的格子更多。

## 7. 进阶：正确性、代价与边界

### 7.1 可采纳与一致性

`h` 可采纳（`h(n) ≤ 真实剩余代价`）时，A\* 第一次弹出终点就是最优解。八方向 octile 距离正好等于无障碍时的最短距离，所以不会高估。更强的是**一致性**：对任意相邻格 `n→n'`，`h(n) ≤ cost(n,n') + h(n')`。octile 距离满足它（直走差 1、对角差 `√2`），所以每个格子第一次被弹出时 `g` 已最优，代码里"弹出后进 closed、不再更新"才是安全的。

### 7.2 复杂度与内存

最坏 `O(V log V)`（`V = W×H`，每个格子可能多次入队）。本工程 100×100：

- `m_blocked`：10,000 字节；
- 每次 `FindPath` 还分配 `gScore`（10,000 × 4 B = 40 KB）、`cameFrom`（40 KB）、`closed`（10 KB），**约 90 KB/次**，并全部清零。

多个 AI 每 0.6 秒重寻路时，这些分配和清零是实打实的开销。教学实现选择"每次新建、逻辑简单"，工业实现会复用缓冲、分帧、或改用 NavMesh/流场。

### 7.3 2.5D 的代价

`RasterizeBoxes` 完全不看盒子的 Y 范围。第三人称关卡里"空中长廊"在 `y ≈ 5`，它的地面投影仍会把下面的格子标成阻挡；反过来，矮台阶也会挡住视线。对平坦场地够用，对多层结构就会出错。真正的 NavMesh 用多边形 + 高度信息，或者分层导航。

### 7.4 其他边界

- **只在场景变化时重建**：`RebuildNavigation` 不在每帧调用；移动的箱子不会更新栅格；
- **没有局部避让**：`NavAgent` 直接 `SetPosition`，不调用 `MoveWithSlide`，所以角色之间会重叠，也可能在平滑后的拐角轻微切角；
- **`WorldToCell` 用的是 `static_cast<int>`（向零截断）而不是 `floor`**：本工程原点在 `-25`，格内坐标为正，截断等于 floor；但采样点落到原点左侧（`worldX < -25`）时，`-0.2/0.5` 会截断成 0，被当成第 0 列。现在因为最外圈永远标阻挡，这个越界点恰好被判成"不可走"，**没有暴露成假通过**；但这是靠边界环掩盖的实现隐患，改原点或去掉边界环就会出错；
- **目标吸附**按方形邻域扫描（`r=1..4`，从 `-r` 到 `+r`），找到第一个可走格就用，不保证欧氏最近。

### 8.1 实验（本次未实际运行）

```bat
build\bin\ErMao.exe --level thirdperson --play --frames 300
```

预期观察（条件性，未实测）：三个红色巡逻者沿随机点巡逻；玩家进入 12 m 且在半角 75° 视野内、视线不被静态盒挡住时切到追击；躲到立柱后，视线检测失败，AI 回到巡逻。启动日志里应出现 `导航网格生成：100 x 100 格（0.50 m/格）`。

排查入口：

1. 日志没有网格行 → `RebuildNavigation` 没被调用，或 `Build` 的宽高算出 0；
2. AI 不追 → 先看 `sightAngleDegrees`（是不是把半角当总角配了）、再看 `HasLineOfSight` 是否被矮盒挡住；
3. AI 追但贴墙卡住 → 检查静态盒是否带 `RigidBody` 且 `isStatic`，栅格是否把它标成阻挡；
4. AI 不动 → `FindPath` 是否因起点在阻挡格返回 false（`RequestPath` 失败会保留旧路径）。
