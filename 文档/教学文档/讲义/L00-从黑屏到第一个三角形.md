## 0. 本讲地图（七步）

- **现象/最简实现**：窗口开了、里面全黑；先每帧清后备缓冲再 `Present`。
- **失败 1/2/3**：清屏画不出东西；3 个顶点只能写死在 shader；有了顶点缓冲，顶点仍在模型空间、相机不参与。
- **正式方案**：顶点/索引缓冲 → 模型-视图-投影（MVP）矩阵 `M/V/P` → 深度 → 常量缓冲/光照 → 实例化。
- **源码落点**：`Device::BeginFrame`、`Mesh::Create`、`Renderer::BuildBatches/DrawBatches`、`PBR.hlsl`。

## 1. 先看现象：窗口开了，为什么是全黑

窗口本身只是画布，真正显示的是**交换链（Swap Chain）**里的**后备缓冲（Back Buffer）**，以及绑定它的**渲染目标视图（Render Target View，RTV）**。
每帧把像素写进去，再 `Present` 交给桌面合成器。若这一帧既没清屏也没画东西，缓冲里就是上一帧或未定义内容，
看起来常常是黑的。这不是“渲染器没启动”，而是“这一帧没有写入任何像素”。

第一步先证明“我能稳定写满整张缓冲”：

**概念伪代码：最小清屏循环**

```cpp
device.Init(&window);             // 设备、交换链、RTV、深度
while (window.Poll()) {
    float clear[4] = {0.1f, 0.2f, 0.3f, 1.0f};
    device.BeginFrame(clear);     // 绑后备缓冲 + 清颜色/深度
    // 什么都不画
    device.EndFrame(true);        // Present(1, 0)
}
```

**源码节选：`rhi/Device.cpp`**

```cpp
scd.BufferCount = 2;
scd.SwapEffect = DXGI_SWAP_EFFECT_FLIP_DISCARD;

void Device::BeginFrame(const float clearColor[4]) {
    ID3D11RenderTargetView* rtv = m_backRTV.Get();
    m_context->OMSetRenderTargets(1, &rtv, m_depthDSV.Get());
    m_context->ClearRenderTargetView(rtv, clearColor);
    m_context->ClearDepthStencilView(m_depthDSV.Get(), D3D11_CLEAR_DEPTH | D3D11_CLEAR_STENCIL, 1.0f, 0);
}

void Device::EndFrame(bool vsync) { m_swapChain->Present(vsync ? 1 : 0, 0); }
```

两个容易误解的点：**后备缓冲 RTV 不是每帧重拿**——`CreateBackbufferViews` 在 `Init` 调用一次，`Resize` 时先解绑/释放，
因为 `ResizeBuffers` 要求先释放所有引用；**正式管线清的不是后备缓冲，而是 HDR 场景目标**——`RenderInternal` 清
`m_sceneTarget`（`R16G16B16A16_FLOAT`），清屏色是 `kClearColor = {0.02, 0.025, 0.035, 1}`，之后还要过天空/PBR/后处理，
所以“只清屏”和“正式管线清屏”的颜色数值不是同一个。

**预期（本次未实际运行）**：只保留 `BeginFrame → EndFrame`，应看到均匀深色；没有清屏时颜色不可作为基线。

| 现象 | 先查 |
|---|---|
| 全黑但设备创建成功 | 是否调用 `BeginFrame`；`Present` 是否返回 |
| 颜色偏暗/偏灰 | 清的是 HDR 场景目标还是后备缓冲；是否过了 Post 的 ACES + gamma |

## 2. 再加一步：画 3 个顶点（仍然没有顶点缓冲）

清屏不证明光栅化器和 shader 能跑。下一步用 `SV_VertexID` 自己生成 3 个顶点：

**概念伪代码：全屏三角形**

```hlsl
struct VSOut { float4 clip : SV_POSITION; };
VSOut VSMain(uint vertexId : SV_VertexID) {
    float2 uv = float2((vertexId << 1) & 2, vertexId & 2);
    VSOut o;
    o.clip = float4(uv * float2(2.0, -2.0) + float2(-1.0, 1.0), 0.0, 1.0);
    return o;
}
```

绘制时 `IASetInputLayout(nullptr)`、拓扑设为 `TRIANGLELIST`，再 `Draw(3, 0)`。

仓库的天空/后处理也这么画，但**深度写的是 1，不是 0**：

**源码节选：`shaders/Sky.hlsl`（`Post.hlsl` 的 `clip` 计算相同，输出字段不同）**

```hlsl
VSOutput VSMain(uint vertexId : SV_VertexID) {
    float2 uv = float2((vertexId << 1) & 2, vertexId & 2);
    VSOutput o;
    o.clip = float4(uv * float2(2.0, -2.0) + float2(-1.0, 1.0), 1.0, 1.0);
    o.ndc = o.clip.xy;
    return o;
}
```

`z=1, w=1` 的 NDC 深度是 1（远平面）。若深度测试还开着、比较函数是 `LESS`，清深度后的 1.0 使 `1 < 1` 不成立，
**一个像素都不会写**。所以 `SkyPass`/`PostPass` 都用 `SetDepthNone` 与 `IASetInputLayout(nullptr)`；天空前的
`SetCullNone` 由 `RenderInternal` 设置，`PostPass` 自己设。**预期（未实际运行）**：PS 输出固定色则整屏该色；跑真实 `Sky.hlsl` 则是天空渐变。

常见失败：深度测试开着且 `z=1`、PS 未绑、viewport 为 0 都会“什么都没有”；只覆盖一部分是顶点坐标或
viewport 不是整窗；被剔除则查绕序（Sky/Post 用 `CullNone` 规避）。这一步只验证管线状态，不能证明会画任意几何体。

## 3. 问题一：三角形写死在 shader 里，立方体怎么办

立方体每个面的顶点位置/法线/UV 都不同，继续在 shader 里 `if (vertexId == ...)` 不可维护，而且逐顶点数据没地方放。
于是需要**顶点缓冲（Vertex Buffer，VB）**：把顶点数组上传 GPU，draw 时按**输入布局（Input Layout）**解释这段内存。

**源码节选：`renderer/Mesh.h` 与 `Renderer.cpp` 的 `kPbrLayout`（只列 slot 0）**

```cpp
struct Vertex { Vec3 position; Vec3 normal; Vec2 uv; }; // 12 + 12 + 8 = 32 B

const D3D11_INPUT_ELEMENT_DESC kPbrLayout[] = {
    {"POSITION", 0, DXGI_FORMAT_R32G32B32_FLOAT, 0,  0, D3D11_INPUT_PER_VERTEX_DATA, 0},
    {"NORMAL",   0, DXGI_FORMAT_R32G32B32_FLOAT, 0, 12, D3D11_INPUT_PER_VERTEX_DATA, 0},
    {"TEXCOORD", 0, DXGI_FORMAT_R32G32_FLOAT,    0, 24, D3D11_INPUT_PER_VERTEX_DATA, 0},
    // 后面还有 slot 1 的 9 个实例属性……
};
```

`kPbrLayout` **不止这 3 行**：后面还有 `TEXCOORD1..9` 共 9 个 `D3D11_INPUT_PER_INSTANCE_DATA`
（世界矩阵 4 列、法线矩阵 3 列、albedo、参数）。只吃 `POSITION` 的教学 shader 不该套这个布局；
若用真实 `PBR.hlsl` 却只绑 slot 0，这些输入默认是 0，世界矩阵退化（无有效平移/旋转），三角形退化。
`Renderer::DrawBatches` 同时绑 slot 0（网格）与 slot 1（实例），stride 分别是 `sizeof(Vertex)` 和 `sizeof(InstanceVertex)`。

**源码节选：`renderer/Mesh.cpp`**

```cpp
vb.ByteWidth = static_cast<UINT>(vertices.size() * sizeof(Vertex));
vb.Usage = D3D11_USAGE_IMMUTABLE;
vb.BindFlags = D3D11_BIND_VERTEX_BUFFER;
device->CreateBuffer(&vb, &init, &m_vertexBuffer);

ib.ByteWidth = static_cast<UINT>(m_data.indices.size() * sizeof(u32));
ib.BindFlags = D3D11_BIND_INDEX_BUFFER;
device->CreateBuffer(&ib, &iinit, &m_indexBuffer);

void Mesh::Draw(ID3D11DeviceContext* ctx, UINT instanceCount) const {
    ctx->DrawIndexedInstanced(m_indexCount, instanceCount, 0, 0, 0);
}
```

**为什么还要索引缓冲**：`primitives::Cube` 的 `AddQuad` 每面压 4 个顶点 + 6 个索引，6 个面就是
**24 个顶点、36 个索引**；不用索引则要写 36 个顶点，重复大量位置/法线/UV。索引让 24 个顶点被 36 次引用，
省显存，也给顶点缓存复用机会；代价是多一次索引绑定和间接寻址。

常见失败：offset/stride 与 `kPbrLayout` 不一致会花屏；只绑 slot 0 没绑 slot 1 或实例 stride 写成
`sizeof(Vertex)` 会让模型变形/消失；背面看不见则查绕序——`PrimitiveMesh.cpp` 约定外侧逆时针，
光栅化状态是 `FrontCounterClockwise=TRUE`、`CullMode=BACK`。

## 4. 问题二：顶点在模型空间，屏幕坐标从哪来

假设立方体顶点是 `(-0.5,-0.5,-0.5)` 到 `(0.5,0.5,0.5)`。顶点着色器输出的 `SV_POSITION` 必须是**裁剪空间**坐标。
直接把模型坐标当裁剪坐标会怎样：

- `x,y ∈ [-0.5,0.5]` 只是归一化设备坐标（Normalized Device Coordinates，NDC）中心一小块，立方体很小；
- `z ∈ [-0.5,0.5]`，D3D 要求 `0 ≤ z ≤ w`，负 z 被裁掉，像切了一半；
- 相机位置/朝向/视场角完全不参与，移动相机画面不动。

所以需要 **模型矩阵 M**（模型→世界）、**视图矩阵 V**（世界→相机）、**投影矩阵 P**（相机→裁剪）。
本工程是列向量约定，复合顺序只有一种：

```
p_clip = P · V · M · p_local
```

从右往左：先 M，再 V，最后 P。等价写法是 `viewProj * world * p`，不是 `world * viewProj * p`。

**概念伪代码：一个最小 MVP 常量缓冲**

```cpp
struct PerObject { Mat4 mvp; };
cb.mvp = camera.ViewProjection() * objectWorld;
ctx->UpdateSubresource(cbBuffer, 0, nullptr, &cb, 0, 0);
```

```hlsl
cbuffer PerObject : register(b0) { float4x4 gMVP; };
VSOut VSMain(VSIn input) { o.clip = mul(gMVP, float4(input.position, 1.0)); }
```

但仓库**没有** `PerObject`：`PerFrameCB::viewProj = camera.ViewProjection()` 每帧一份（`b0`），
每个物体的世界矩阵作为实例属性 `TEXCOORD1..4` 传入；VS 里先 `worldPos = M*p`，再 `clip = mul(gViewProj, worldPos)`。

**源码节选：`renderer/Camera.h` 与 `shaders/PBR.hlsl`**

```cpp
Mat4 ViewProjection() const { return Projection() * View(); }
```

```hlsl
float4 worldPos = ApplyWorld(float4(input.position, 1.0), input.col0, input.col1, input.col2, input.col3);
o.clip = mul(gViewProj, worldPos);
```

`ApplyWorld` 内部用 `mul(p, W)`（4 个“列”拼成的矩阵）等价于 `W_math * p`；净效果仍是先 M、再 VP。
细节与转置关系见[第 4 讲](L04-渲染管线与坐标空间.md)。

### 深度缓冲：遮挡为什么错

没有深度缓冲时后画的像素总是覆盖先画的；多个物体互相遮挡、或网格面彼此穿插时，遮挡会随绘制顺序变化（单个闭合立方体开了背面剔除时背面不画，问题不明显）。本工程链路：

1. `CreateBackbufferViews` 创建 `D24_UNORM_S8_UINT` 深度纹理和 DSV；
2. `BeginFrame` 把深度清成 `1.0f`；
3. 不透明 Pass 用 `SetOpaque`：深度测试 `LESS`、深度写入开启；
4. 天空/后处理用 `SetDepthNone`；阴影用独立 `DepthTarget`（2048²）。

常见失败：`viewProj * world` 写成 `world * viewProj`，或实例数据没绑导致世界矩阵退化，都会让物体消失；深度没绑/没清、
不透明 Pass 没开深度写入会让遮挡错乱；上下颠倒查投影矩阵 Y 符号与 D3D NDC/视口 Y 方向；
近处被裁查 `nearZ` 太大或顶点在相机背后（`w <= 0`）。

## 5. 问题三：颜色全一样，怎样看出光照

真实光照至少需要逐顶点法线（已在 `Vertex`）、光源方向/颜色/强度、材质参数，以及把它们送进 shader 的
**常量缓冲（Constant Buffer，CB）**。D3D11 要求 CB 按 16 字节对齐，C++ 结构体必须与 HLSL `cbuffer` 逐字节一致，
否则“只改一个 float，颜色整体错位”。仓库用编译期检查兜底：

**源码节选：`rhi/Buffer.h` 与 `renderer/Renderer.h`（省略成员函数、同类型字段合并书写，布局不变）**

```cpp
template <typename T> class ConstantBuffer {
    static_assert(sizeof(T) % 16 == 0, "常量缓冲大小必须是 16 的倍数");
};

struct PerFrameCB {
    Mat4 viewProj, lightViewProj, invViewProj; // 3*64
    Vec4 cameraPosTime, sunDirIntensity, sunColorTexel, ambientUpCount;
    Vec4 ambientDownExposure, shadowParams, misc; // 7*16
}; // 304 B
```

每个物体的材质参数不放 CB，而和世界矩阵一起塞进 144 B 的 `InstanceVertex`
（`col0..col3` 64 + `nrm0..nrm2` 48 + `albedo` 16 + `params` 16）。这样一次 draw 能画很多同网格物体，
不必每物体 `UpdateSubresource` 一次——这是**实例化（Instancing）** 的动机，详见[第 4 讲](L04-渲染管线与坐标空间.md)
与[第 22 讲](L22-GPU%20Driven.md)。

**源码节选（省略中间行）：`shaders/PBR.hlsl`**

```hlsl
float4x4 NM = float4x4(input.nrm0, input.nrm1, input.nrm2, float4(0, 0, 0, 0));
o.normal = mul(float4(input.normal, 0.0), NM).xyz;
...
float3 sunL = normalize(gSunDirIntensity.xyz);
color += ShadePoint(N, V, sunL, gSunColorTexel.rgb * gSunDirIntensity.w, baseColor, roughness, metallic) * shadow;
```

法线用**逆转置矩阵** `transpose(inverse(world))` 变换；非均匀缩放下直接乘世界矩阵会让法线歪掉，
反例见[第 4 讲 §9](L04-渲染管线与坐标空间.md)。

常见失败：光照全黑先查法线是否为 0（实例法线没绑）、`N·L < 0`（光在背面）或太阳方向取反；
颜色整体错位查 C++ `PerFrameCB` 与 HLSL `cbuffer` 字段顺序/大小；非均匀缩放下异常查 `nrm*` 是否逆转置。

## 6. 回到引擎的“一帧”

现在再看 `Renderer::RenderInternal`，每个 Pass 都只是“绑状态 + 画一批顶点”：

**源码节选：`renderer/Renderer.cpp`（保留调用顺序）**

```cpp
BuildBatches(camera, scene, !GpuCullEnabled()); // CPU 剔除/分批/实例数据
UploadInstances(ctx);
ShadowPass(ctx);                 // 深度-only，太阳视角
m_sceneTarget.Bind(ctx);         // HDR RGBA16F + 深度
m_sceneTarget.Clear(ctx, kClearColor);
SkyPass(ctx);                    // 全屏三角形，无深度
OpaquePass(ctx, wireframe);      // GpuCulledDraw + SkinnedPass
ParticlePass(ctx); DebugPass(ctx);
PostPass(ctx, outputRtv, ...);   // 全屏三角形，ACES + gamma
```

两个容易看漏的点：**`SkinnedPass` 不是顶层 Pass**，由 `OpaquePass` 在 `GpuCulledDraw` 之后调用；
**2D 路径是另一条**，`scene.is2D == true` 时直接 `SpritePass`，不跑 Shadow/Sky/PBR/Post。
`Renderer::Render` 先渲染到离屏视口纹理，再 `CopyPass` 到后备缓冲；编辑器用 `RenderToViewport` 拿 SRV 给
`ImGui::Image`。所以屏幕上的一个像素可能经过 HDR 场景缓冲、后处理、拷贝/ImGui 中的一步或几步。

## 7. 小例子：3 个顶点怎样变成像素

不涉及 MVP，只看“裁剪空间 → 视口”。设 viewport 1280×720：

| 顶点 | 裁剪 `(x,y,z,w)` | NDC `(x/w,y/w)` | 像素 `(px,py)` |
|---|---|---|---|
| v0 | `(-0.5,-0.5,0.5,1)` | `(-0.5,-0.5)` | `(320,540)` |
| v1 | `( 0.5,-0.5,0.5,1)` | `( 0.5,-0.5)` | `(960,540)` |
| v2 | `( 0.0, 0.5,0.5,1)` | `( 0.0, 0.5)` | `(640,180)` |

换算：`px=(ndc.x*0.5+0.5)*W`，`py=(0.5-ndc.y*0.5)*H`（屏幕 y 向下）。
底边从 `(320,540)` 到 `(960,540)`，顶点在 `(640,180)`。中间状态：清屏后整屏 clear 色；光栅化后三角形覆盖区被 PS 写成固定色；只有一个不透明三角形时，
深度写不写都不影响结果。把 v0 的 y 从 -0.5 改成 0.5，底边跑到屏幕上方，三角形翻转。

## 9. 自测题

1. 为什么 `BeginFrame` 要同时清颜色和深度？只清颜色会怎样？
2. `D3D11_USAGE_IMMUTABLE` 的顶点/索引缓冲意味着什么？什么时候不能这么用？
3. `kPbrLayout` 的 offset 是谁和谁的契约？`Vertex` 中间插入一个 `float` 会怎样？
4. 全屏三角形 `z=1` 为什么也能画出来？普通不透明物体呢？
5. 为什么世界矩阵放实例属性，而不是每个物体一个 `PerObject` 常量缓冲？

**答案**

1. 深度也要从 1.0 开始，否则上一帧深度参与本帧比较，近处物体可能被旧深度挡住；只清颜色会出现随帧变化的遮挡错误。
2. GPU 只读、CPU 不再改，适合静态网格；每帧改顶点（粒子/蒙皮）应用 `DYNAMIC` 或 `DEFAULT + UpdateSubresource`。
3. 是 `Vertex` 布局、`kPbrLayout` 的 offset/format、HLSL `VSInput` 三者的契约；插入字段后后续 offset 与 stride 都要改。
4. 因为 `SkyPass`/`PostPass` 用 `SetDepthNone`，深度测试不参与；普通不透明物体在 `LESS` 下写 `z=1` 会与清深度的 1.0 比较失败而被丢弃。
5. 为了批处理/实例化：`PerObject` 意味着每物体一次 `UpdateSubresource` + 一次 draw；实例属性允许同网格同材质一次 `DrawIndexedInstanced`，代价是实例数据占顶点带宽。
