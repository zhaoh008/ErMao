## 0. 本讲地图

- **现象**：角色走动，手里的剑跟着走；父物体旋转，子物体绕父物体转，而不是绕世界原点转。
- **最简实现**：每个物体存位置/旋转/缩放，`Local=T·R·S`，`World=Parent.World·Local`。
- **具体失败**：变换顺序写反、欧拉角万向锁、层级缓存漏更新、非均匀缩放产生剪切。
- **正式方案/源码**：平移-旋转-缩放（TRS）、矩阵复合、四元数、Slerp、逆变换；对照 `Mat4`、`Transform::ToMatrix`、`Quat::Slerp`、
  `GameObject::LocalMatrix/WorldMatrix`、`Skeleton::ComputeWorld`。
- **可验算例子**：父 `(2,0,0)`、绕 Y 90°、缩放 `(2,1,1)`，子局部 `(1,0,-1)` → 世界 `(1,0,-2)`。

## 1. 先看现象：子物体为什么跟着父物体

在 UE 里把剑挂到角色手部插槽，角色走剑跟着走；角色转身，剑绕角色转。不用父子关系，每帧都要手算剑的世界位置。
最自然的想法是：每个物体只描述“相对父物体”的变换，渲染时再一路乘到世界。

**概念伪代码：最朴素的层级变换**

```cpp
struct Transform { Vec3 position{0,0,0}; float yaw = 0.0f; Vec3 scale{1,1,1}; };

Mat4 LocalMatrix(const Transform& t) {
    return Mat4::Translation(t.position) * Mat4::RotationY(t.yaw) * Mat4::Scale(t.scale);
}
Mat4 WorldMatrix(const Node& n) {
    return n.parent ? WorldMatrix(*n.parent) * LocalMatrix(n.transform) : LocalMatrix(n.transform);
}
```

这能跑，也能解释“子物体跟随父物体”，但会在四个地方具体地坏掉。

## 2. 四个具体失败

### 2.1 顺序写反：物体绕世界原点公转

列向量约定下从右往左作用：`T·R·S` 先缩放、再旋转、最后平移。若写成 `R·T·S`，平移先发生、再被旋转，
物体会绕**世界原点**转，而不是绕自己转。取 `t=(2,0,0)`、绕 Y `+90°`、点 `p=(1,0,0)`：

`T·R·S` 先算 `R·p=(0,0,-1)` 再加 `t`，得 `(2,0,-1)`；`R·T·S` 先算 `p+t=(3,0,0)` 再旋转，得 `(0,0,-3)`。
同一个点、同一个旋转，结果差了一个“绕原点”的位移。

矩阵乘法不交换，`T·R ≠ R·T`，所以顺序必须写死；`Transform::ToMatrix()` 与 `BoneTransform::ToMatrix()` 都返回 `T * R * S`。

### 2.2 欧拉角顺序与万向锁

旋转不止一个轴时，必须回答“先绕哪个轴”。本工程用 UE 风格 YXZ：`yaw` 绕 Y、`pitch` 绕 X、`roll` 绕 Z，
代码是 `qy*qp*qr`；作用到向量时最右边的先作用：先 roll，再 pitch，最后 yaw。换个顺序结果就不同，
所以“欧拉角”必须附带顺序约定；编辑器可以显示/输入，内部不要拿三个角直接插值。

更糟的是**万向锁（Gimbal Lock）**：`pitch=±90°` 时 yaw 轴与 roll 轴重合，三自由度退化成两个。
`Quat::ToEuler` 在 `|sp|>=0.9999` 时只解一个 yaw、把 roll 置 0——**同一个旋转可能对应无数组欧拉角**。
从欧拉角插值到欧拉角，接近 ±90° 时可能突然“翻面”；四元数没有这个问题，代价是多一个模长约束，且 `q` 与 `-q` 同旋转。

### 2.3 层级缓存漏更新：子物体“慢半拍”

若给每个节点缓存世界矩阵，只在“自己”的 position 变化时失效，父节点变了子节点没失效，子物体会停在旧位置。
典型现象：拖父物体，子物体延迟一帧或不动；旋转父物体，子物体不跟着转。

本工程的实际选择与常见的“缓存 + 脏标记”写法不同，必须按源码说：

**源码节选：`scene/GameObject.cpp`**

```cpp
void GameObject::MarkWorldDirty() {
    m_worldDirty = true;
    for (auto* child : m_children) child->MarkWorldDirty();
}

const Mat4& GameObject::WorldMatrix() const {
    // 这里选择"每次重算"而不是维护脏标记。
    m_worldMatrix = m_parent ? m_parent->WorldMatrix() * LocalMatrix() : LocalMatrix();
    return m_worldMatrix;
}
```

`m_worldDirty` 被 `SetPosition/SetRotation/SetScale/SetParent` 置位并递归传播给子节点，但 **`WorldMatrix()` 从不读它**。
所以不会出现“父变子不变”的缓存 bug——因为每次都重算；代价是每次查询沿父链做 `depth` 次 4×4 乘法，复杂度 `O(depth)`。
`SetPosition` 仍递归遍历子树去置一个没人读的标记，这部分遍历目前是白做的。
若改成真正的缓存，必须让 `WorldMatrix()` 检查 `m_worldDirty`；否则 `m_worldMatrix` 的写入只是重复劳动。

### 2.4 非均匀缩放：父物体的拉伸会让子物体剪切

父 `scale=(2,1,1)`、子缩放取 1、子绕 Z 转 45°，子世界矩阵上半部分是 `R_p·S_p·R_c`（父旋转取单位阵时就是 `S·R`）：

```
S·R45 = diag(2,1,1)·Rz(45°) 的两列 = (1.414, 0.707, 0) 与 (-1.414, 0.707, 0)
```

第 0 列 `(1.414,0.707,0)` 与第 1 列 `(-1.414,0.707,0)` 的点积是 `-2+0.5=-1.5 ≠ 0`，不再正交：
正方形被拉成平行四边形，这就是**剪切（Shear）**。`S·R` 一般不能写成“某个旋转 × 某个缩放”，
所以子世界矩阵无法再分解成干净的 TRS；渲染点坐标仍正确，但反推 position/rotation/scale 会出错，法线要用逆转置（见[第 4 讲 §9](L04-渲染管线与坐标空间.md)）。

## 3. 正式方案：TRS、父子复合、四元数

### 3.1 数据与运算

局部变换存三样：`position`（相对父原点的平移，世界单位）、`rotation`（单位四元数，无量纲）、
`scale`（三轴缩放，1 为原尺寸）。局部矩阵与父子复合：

```
M_local = T(position) · R(rotation) · S(scale)
M_world(child) = M_world(parent) · M_local(child)
p_world = M_world · p_local
```

从右往左：先子局部，再父局部，再祖父……直到根；根节点 `M_world=M_local`。逆变换用于“世界→局部”（拾取、把射线变到模型空间）：

```
M^{-1} = S^{-1} · R^{-1} · T^{-1} = S^{-1} · R^T · T(-t)
```

旋转矩阵正交，`R^{-1}=R^T`，比通用 4×4 求逆快且稳定；`Mat4::Inverse()` 走高斯-约当消元，奇异矩阵返回单位阵。

### 3.2 四元数

单位四元数 `q=(x,y,z,w)=(sin(θ/2)·a, cos(θ/2))`，`a` 是单位轴，`θ` 是旋转角。对向量 `v`：

```
v' = q · v · q*          // q* 是共轭；单位四元数下 q* = q^{-1}
```

展开成矩阵就是 `Quat::ToMat4()` 的 3×3：

```
        | 1-2(y²+z²)   2(xy - zw)   2(xz + yw) |
R(q) =  | 2(xy + zw)   1-2(x²+z²)   2(yz - xw) |
        | 2(xz - yw)   2(yz + xw)   1-2(x²+y²) |
```

复合：先转 `q1` 再转 `q2`，总旋转 `q2·q1`（右边先作用，和矩阵一致）。
欧拉角、矩阵、四元数的取舍：

| 表示 | 存储 | 插值 | 万向锁 | 复合 |
|---|---|---|---|---|
| 欧拉角 | 3 float | 不能直接插（角度环绕） | 有（pitch=±90° 丢一维） | 需转矩阵/四元数 |
| 旋转矩阵 | 9 float | 不能直接插（破坏正交性） | 无 | 矩阵乘 |
| 四元数 | 4 float | Slerp（球面最短路径） | 无 | 四元数乘 |

### 3.3 Slerp

两个单位四元数夹角 `Ω`，`cosΩ=q0·q1`：

```
slerp(q0,q1,t) = ( sin((1-t)Ω)·q0 + sin(tΩ)·q1 ) / sinΩ
```

两个细节：`Ω→0` 时除以 `sinΩ` 不稳定，代码在 `cosTheta>0.9995` 时退化为线性插值再归一化；
若 `q0·q1<0`，两个四元数在对跖点（同一旋转的两种表示），先取反 `q1=-q1` 走短弧，否则“转一大圈”。

**源码节选（缩短）：`core/Math.h` 的 `Quat::Slerp`**

```cpp
float cosTheta = a.x*b.x + a.y*b.y + a.z*b.z + a.w*b.w;
Quat bb = b;
if (cosTheta < 0.0f) { bb = {-b.x,-b.y,-b.z,-b.w}; cosTheta = -cosTheta; } // 最短路径
if (cosTheta > 0.9995f) return Quat{Lerp(a.x,bb.x,t),Lerp(a.y,bb.y,t),Lerp(a.z,bb.z,t),Lerp(a.w,bb.w,t)}.Normalized();
const float theta = std::acos(Clamp(cosTheta, -1.0f, 1.0f));
const float wa = std::sin((1.0f - t) * theta) / std::sin(theta);
const float wb = std::sin(t * theta) / std::sin(theta);
return {a.x*wa + bb.x*wb, a.y*wa + bb.y*wb, a.z*wa + bb.z*wb, a.w*wa + bb.w*wb};
```

**数值演算**：`q0=(0,0,0,1)`（0°），`q1=(0,sin45°,0,cos45°)`（绕 Y 90°），`t=0.5`。

```
dot = cos45° = 0.7071；Ω = 45°
slerp = (sin22.5°·q0 + sin22.5°·q1) / sin45° = 0.5412·q0 + 0.5412·q1
      = (0, 0.3827, 0, 0.9239)         // 绕 Y 45°
```

`2·asin(0.3827)=45°`，正好一半。不归一化 lerp 在 `t=0.5` 得 `(0,0.3536,0,0.8536)`，模长 0.9239，归一化后相同；
区别在等角速度：lerp 两端慢、中间快，动画会“一顿一顿”，所以仍要用 Slerp。

## 4. 回到本仓库：矩阵约定与真实符号

### 4.1 存储与乘法

**源码节选：`core/Math.h`**

```cpp
// Mat4 为「列主序」存储：m[col][row]，与 HLSL 的 float4x4 内存布局一致；
// 向量是列向量，变换写作 v' = M * v；C = A * B 表示「先 B 后 A」。
float m[4][4];
// C.m[c][r] = Σ_k A.m[k][r] * B.m[c][k]
```

`m[col][row]` 很容易看反：`m[3][0]` 是“第 3 列第 0 行”，即平移的 x；`TransformPoint` 的
`x' = m[0][0]x + m[1][0]y + m[2][0]z + m[3][0]` 与列向量约定一致。

### 4.2 局部矩阵、父子矩阵、四元数

**源码节选：`core/Math.h` 与 `scene/GameObject.cpp`**

```cpp
struct Transform {
    Vec3 position{0,0,0}; Quat rotation{}; Vec3 scale{1,1,1};
    Mat4 ToMatrix() const {
        return Mat4::Translation(position) * rotation.ToMat4() * Mat4::Scale(scale);
    }
};

Mat4 GameObject::LocalMatrix() const {
    return Mat4::Translation(m_position) * m_rotation.ToMat4() * Mat4::Scale(m_scale);
}
```

`Quat::ToMat4()` 的 3×3 就是 §3.2 的矩阵，逐项对应 `m[col][row]`。
骨骼走同一套数学：

**源码节选（缩短）：`animation/Skeleton.cpp`**

```cpp
Mat4 BoneTransform::ToMatrix() const {
    // 局部变换 = T * R * S（列向量约定：先缩放、再旋转、最后平移）
    return Mat4::Translation(translation) * QuatToMatrix(rotation) * Mat4::Scale(scale);
}

void Skeleton::ComputeWorld(const std::vector<BoneTransform>& local, std::vector<Mat4>& world) const {
    for (size_t i = 0; i < bones.size(); ++i) {
        const Mat4 localMatrix = ...;
        const int parent = bones[i].parent;
        world[i] = (parent >= 0) ? world[parent] * localMatrix : localMatrix;
    }
}
```

`Skeleton::ComputeWorld` 按数组顺序遍历，`AddBone` 只 `push_back`、不检查父索引；调用方（如 `SkinningDemo` 用 `i-1`）
必须保证父骨骼先加入。若父索引大于子索引，`world[parent]` 还没算，结果就错了——这是“层级更新顺序”的另一种表现。

### 4.3 旋转怎么存、怎么归一化

`GameObject::SetRotation`（**源码节选**）只在“明显不是单位四元数”时才归一化：

```cpp
const float length = std::sqrt(q.x*q.x + q.y*q.y + q.z*q.z + q.w*q.w);
m_rotation = (std::fabs(length - 1.0f) > 1e-4f) ? q.Normalized() : q;
```

原因是每次“加载→保存”都归一化会让四元数漂 1 ULP，场景文件无法做到序列化幂等。
`World::ToJson` 把旋转写成 `[x,y,z,w]` 四个数，读回时 `SetRotation(Quat(...))`。
所以旋转在存档里就是四个 float，不是欧拉角；欧拉角只在编辑器显示/输入时用 `ToEuler/FromEuler` 转换。

## 5. 可独立验算的父子变换

设父：`position_p=(2,0,0)`、`rotation_p=绕 Y +90°`（四元数 `(0,sin45°,0,cos45°)`）、`scale_p=(2,1,1)`。
子：局部平移 `t_c=(1,0,-1)`（相对父：右 1、前 1）、旋转单位四元数、缩放 1。

父旋转矩阵（由 `ToMat4` 代入 `x=0,y=sin45,z=0,w=cos45`）：

```
R_p = | 0  0  1 |
      | 0  1  0 |
      | -1 0  0 |
```

它把局部 `+X` 映射到世界 `-Z`，把局部 `-Z`（前方）映射到世界 `-X`。父世界矩阵 `M_p=T(2,0,0)·R_p·S(2,1,1)`。
子原点经 `M_world=M_p·T(1,0,-1)`：

| 步骤 | 计算 | 结果 |
|---|---|---|
| 子平移 | `T_c·0` | `(1,0,-1)` |
| 父缩放 | `S_p·(1,0,-1)` | `(2,0,-1)`（局部 +X 被拉成 2） |
| 父旋转 | `R_p·(2,0,-1)` | `(-1,0,-2)`（局部 +X→世界 -Z，局部 -Z→世界 -X） |
| 父平移 | `+(2,0,0)` | `(1,0,-2)` |

直观检查：父在 `x=2`、朝世界 `-X`；子在父的“前方 1 米、右方 1 米”，前方把 x 减 1；右方（局部 +X）先被父 `scale.x=2` 拉成 2 米，再经父旋转指向世界 -Z，所以 z 减 2，得到 `(1,0,-2)`。

**逆变换验算**：把 `(1,0,-2)` 变回子局部：

```
T_p^{-1}: (-1,0,-2)
R_p^T:    → (2,0,-1)
S_p^{-1}: → (1,0,-1)   ✓
```

`R_p` 正交，`R_p^{-1}=R_p^T`，不需要通用求逆。

**四元数复合验算**：父 `q_p=绕Y90°`，子再加 `q_c=绕Y90°`：

```
q_total = (0,sin45,0,cos45) * (0,sin45,0,cos45)
        = (0, 2·sin45·cos45, 0, cos²45 - sin²45)
        = (0, 1, 0, 0)          // 绕 Y 180°
```

把前方 `(0,0,-1)` 转 180° 得 `(0,0,1)`；父单独 90° 时前方是 `(-1,0,0)`，再加 90° 变成 `(0,0,1)`，与总 180° 一致。
注意复合顺序：`q_p*q_c` 表示先子后父（右边先作用），和矩阵一致。

## 6. 常见错误与对应现象

| 错误 | 现象 | 修正 |
|---|---|---|
| `Local=R·T·S` | 物体绕世界原点公转 | `T·R·S`，列向量从右往左 |
| 欧拉角直接插值 | 359°→1° 反向转一大圈；接近 ±90° 翻面 | 转四元数后 Slerp |
| Slerp 不处理负点积 | 某些角度“转一大圈” | `dot<0` 时取反 |
| 层级缓存只失效自己 | 父动子不动/慢半拍 | 失效传播到子树，或像本工程每次重算 |
| 非均匀缩放 + 子旋转 | 子物体被剪切，无法反解 TRS | 避免父子非均匀缩放；法线用逆转置 |

## 8. 自测题

1. 证明旋转矩阵 `R^{-1}=R^T`。答案：正交矩阵定义 `R^T R=I`，两边右乘 `R^{-1}` 即得。
2. 手算 `q=(0,sin45°,0,cos45°)` 把 `(1,0,0)` 转到哪。答案：绕 Y +90°，`(1,0,0)→(0,0,-1)`。
3. 为什么 `T·R·S` 里 S 放最后？答案：列向量从右往左，先缩放再旋转再平移；换顺序会改变旋转中心/结果。
4. Slerp 里 `q0·q1<0` 取反，几何上意味着什么？答案：两个四元数在对跖点，表示同一旋转；取反走 4D 球面短弧，避免“转一大圈”。
5. `WorldMatrix()` 有没有用脏标记？答案：没有，标记被设置但函数每次重算（§2.3）。
