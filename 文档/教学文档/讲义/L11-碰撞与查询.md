## 1. 两个能观察到的现象
- 在编辑器视口里左键点一下木箱，它被选中；点它旁边的空气，取消选中。屏幕是二维的，物体是三维的，中间必须有一条**从眼睛出发的射线**。
- 第三人称角色按 W 撞向矮墙，停在墙前；贴着墙按 A/D 会沿着墙滑，而不是穿过去。这里问的是**角色占的那块空间和墙的 AABB 有没有重叠、往哪个方向推开**。

同一个问题还有几个变体：脚下有没有地面（向下射线）、AI 能不能看见玩家（眼睛到玩家的射线有没有被挡）、子弹有没有打中敌人（点/球和目标的距离）。它们都可以归成两类查询：**射线求交**和**重叠/距离求交**。
## 2. 最简实现
### 2.1 AABB 重叠：三个区间同时重叠
**AABB（Axis-Aligned Bounding Box，轴对齐包围盒）** 用两个点表示：`min` 和 `max`，六个面分别平行于 X/Y/Z 轴。两个 AABB 相交，当且仅当三个轴上的区间都重叠：

```
overlap_x = a.min.x <= b.max.x && b.min.x <= a.max.x
overlap_y = a.min.y <= b.max.y && b.min.y <= a.max.y
overlap_z = a.min.z <= b.max.z && b.min.z <= a.max.z
相交 = overlap_x && overlap_y && overlap_z
```

**概念伪代码**：

```cpp
bool Overlap(const AABB& a, const AABB& b) {
    return a.min.x <= b.max.x && b.min.x <= a.max.x &&
           a.min.y <= b.max.y && b.min.y <= a.max.y &&
           a.min.z <= b.max.z && b.min.z <= a.max.z;
}
```

边界要不要算"相交"是个约定问题：本工程的盒-盒分支用的是严格 `<` / `>`（`PhysicsWorldSim.cpp:199`），两个面刚好贴上算不重叠；射线求交里则把贴面算命中。写代码时要统一，否则会出现"看起来贴着却没碰撞"。
### 2.2 射线与 AABB：slab 法
**射线（Ray）** 写成 `p(t) = o + d·t`，`o` 是起点，`d` 是方向，`t >= 0` 是参数。若 `d` 是单位向量，`t` 就是距离；否则 `t` 的单位是 `1/|d|`，这一点在比较 `maxDistance` 时必须注意。

**slab 法**把 AABB 看成三对平行平面（x、y、z 各一对）。射线在每一维上进入/离开该维区间的参数是：

```
t1 = (min[i] - o[i]) / d[i]
t2 = (max[i] - o[i]) / d[i]
if (t1 > t2) swap(t1, t2)     // 让 t1 是进入、t2 是离开
tmin = max(tmin, t1)          // 三个轴都进入，才算进入盒子
tmax = min(tmax, t2)          // 任一轴离开，就离开盒子
if (tmin > tmax) 不相交
```

**概念伪代码**：

```cpp
float tmin = 0.0f, tmax = FLT_MAX;
for (int i = 0; i < 3; ++i) {
    if (fabs(d[i]) < 1e-6f) {
        if (o[i] < box.min[i] || o[i] > box.max[i]) return false; // 平行且在板外
    } else {
        float t1 = (box.min[i] - o[i]) / d[i];
        float t2 = (box.max[i] - o[i]) / d[i];
        if (t1 > t2) swap(t1, t2);
        tmin = max(tmin, t1);
        tmax = min(tmax, t2);
        if (tmin > tmax) return false;
    }
}
return true;
```
### 2.3 从鼠标到射线
`Camera::ScreenToRay` 负责把像素变成世界空间射线（**源码节选**，`Camera.cpp:11-30`，省略了 `w ≈ 0` 的退化保护）：

```cpp
const float ndcX = (2.0f * screen.x / screenSize.x) - 1.0f;
const float ndcY = 1.0f - (2.0f * screen.y / screenSize.y);
const Mat4 invVP = ViewProjection().Inverse();
Vec4 p0 = invVP * Vec4(ndcX, ndcY, 0.0f, 1.0f); // 近平面
Vec4 p1 = invVP * Vec4(ndcX, ndcY, 1.0f, 1.0f); // 远平面
p0 = p0 / p0.w; p1 = p1 / p1.w;
Ray ray; ray.origin = p0.xyz();
ray.direction = Normalize(p1.xyz() - p0.xyz());
```

D3D 的 NDC z 是 `[0, 1]`，所以 `z=0` 是近平面、`z=1` 是远平面。射线起点在近平面上，而不是相机原点；比近平面更近的物体不会被这刀切到。编辑器拾取就是 `ScreenToRay` → `World::Raycast` → 取最近命中（`EditorUI.cpp:1582`）。
## 3. 让最简实现具体地失败
### 3.1 旋转物体的 AABB 太大
AABB 不跟着物体旋转，它跟着**世界轴**。一个边长为 1 的立方体绕 Y 转 45° 后，局部角点 `(±0.5, ±0.5, ±0.5)` 变成世界坐标，x 和 z 的半宽都变成

```
0.5·(|cos45°| + |sin45°|) = 0.5·(0.707 + 0.707) = 0.707
```

于是世界 AABB 的尺寸变成 `1.414 × 1 × 1.414`，体积是原来的 **2 倍**。如果是一块 `2 m × 0.1 m` 的薄板绕 Y 转 45°，它的 AABB 在 XZ 上会膨胀到约 `1.48 m × 1.48 m`：射线从薄板旁边的空气穿过，也会被判定为"命中薄板"。

后果分两种：

- 拾取：点空气选中了薄板（**假阳性**），因为 AABB 比真实几何大；
- 遮挡：AI 视线被薄板旁边"不存在的空气"挡住。

AABB 是真实网格的**外包**，所以不会漏掉真实几何（假阴性），只会多报。要更紧，就得上 **OBB（Oriented Bounding Box，有向包围盒）** 或直接用三角形。
### 3.2 逐个测试太慢
`World::Raycast` 对场景里每个带 `MeshRenderer` 的活动物体都做一次 AABB 求交，复杂度是 `O(n)`。一次点击 100 个物体就是 100 次测试；如果每帧有几十条 AI 视线射线，就是几十乘 `n`。对象到几千个时，线性扫描会成为瓶颈。

本工程还多一层开销：`CollectMeshAABBs` 每次调用都重新收集并计算所有物体的世界 AABB。角色控制器在**每个固定步**都调用它（`ThirdPersonController.cpp:169`），也就是每 1/60 秒重建一次全场景包围盒列表。当前教学关卡对象少，这点开销可以接受，但它是"对象一多就慢"的直接入口。
### 3.3 离散采样会"穿透"
这里要区分两种"射线"：

1. **真正的射线查询**（`World::Raycast`）是解析求交，数学上不会穿过 AABB；它的问题不是漏检，而是把整个网格当成盒子（3.1 的假阳性）。
2. **玩法里的命中检测**往往不是射线，而是"每帧把子弹移动一点，再测一次距离"。这种采样会漏。

刷怪 Demo 的子弹就是后者（`WaveGame.cpp:106-130`）：`OnUpdate(dt)` 里先 `position += velocity * dt`，再对所有敌人做 `Length(toTarget) < 0.75f` 的距离判断。弹速默认 `34 m/s`：

| 帧率 / `dt` | 一帧位移 | 与 0.75 m 判定半径的关系 |
|---|---|---|
| 60 fps，`dt = 1/60` | 0.567 m | 小于 0.75，通常能命中 |
| 30 fps，`dt = 1/30` | 1.133 m | 大于 0.75，可能整帧跳过敌人 |
| 卡顿，`dt` 被夹到 0.1 | 3.4 m | 几乎必然穿过 |

这不是精度问题，是**采样点之间没有检测**。真正的修法是扫掠球/胶囊（swept sphere/capsule）或连续碰撞检测（CCD），本工程都没有。

角色移动也有同类问题：`position += velocity*dt` 之后才做推离。正常 `runSpeed = 7.8`、`dt = 1/60` 时一步约 0.13 m，小于矮墙 0.5 m 的厚度；但把 `runSpeed` 调到 30（Inspector 上限）就是 0.5 m/步，已经可能一步跨过薄墙。
### 3.4 退化情况
- **射线与某个轴平行**：`d.x = 0`，不能除。本工程 `IntersectRayAABB` 显式判断 `|d| < kEpsilon`，若原点在板外直接返回 false。不能依赖"`1/0 = ±∞`，IEEE 语义自动正确"；这份实现显式处理了平行情况。
- **射线起点在 AABB 内部**：`tmin` 初始为 0，三个轴的进入参数都为负，所以返回 `true`、`t = 0`，且 `hitAxis = -1`、法线为零向量。这不是错误，但调用方要意识到"命中自己"是可能的。
- **`maxDistance` 是严格小于**：`Raycast` 里写的是 `t < best`，`best` 初值是 `maxDistance`；正好等于 `maxDistance` 的命中不会被接受。
- **方向未归一化**：slab 返回的 `t` 不是米；把它和 `maxDistance`（米）比就会错。
## 4. 逐步引入正式方案
### 4.1 OBB 与分离轴定理（SAT）
**OBB** 用"中心 + 三个正交轴 + 三个半尺寸"表示，能跟着物体旋转。两个凸多面体是否相交，可以用**分离轴定理（Separating Axis Theorem，SAT）**：只要存在一条轴，使两个物体在这条轴上的投影区间不重叠，它们就不相交。

对两个 OBB，候选轴是 15 条：

- A 的 3 条本地轴；
- B 的 3 条本地轴；
- A 的每条轴与 B 的每条轴叉乘，`3 × 3 = 9` 条。

每条轴都把 8 个顶点投影成 `[min, max]` 两个数，再套 2.1 的区间重叠。只要有一条轴分离就提前退出；15 条都重叠才相交。AABB vs AABB 只需要 3 条轴，所以它快，但也更松。

本工程的 `Math.h` 只有 `AABB`，没有 `OBB` 类型，也没有 SAT 实现（**尚未实现的设计**）。第 22 讲 GPU 剔除里用的是 AABB + 视锥平面，不是 OBB。
### 4.2 slab 法的实现细节
**源码节选**（`Math.h:428-454`，省略了 `hitAxis/hitSign` 的声明和最后写 `normal` 的几行）：

```cpp
tmin = 0.0f;
float tmax = FLT_MAX;
for (int i = 0; i < 3; ++i) {
    const float d = ray.direction[i];
    const float o = ray.origin[i];
    if (std::fabs(d) < kEpsilon) {
        if (o < box.min[i] || o > box.max[i]) return false;
    } else {
        const float inv = 1.0f / d;
        float t1 = (box.min[i] - o) * inv;
        float t2 = (box.max[i] - o) * inv;
        float sign = -1.0f;
        if (t1 > t2) { std::swap(t1, t2); sign = 1.0f; }
        if (t1 > tmin) { tmin = t1; hitAxis = i; hitSign = sign; }
        if (t2 < tmax) tmax = t2;
        if (tmin > tmax) return false;
    }
}
```

几个容易看漏的点：

- `tmin` 从 0 开始，所以起点在盒内时返回 `t = 0`，不是负的进入距离；
- 法线的符号由 `t1/t2` 是否交换决定：`d > 0` 时从 `min` 面进入，外法线是 `-axis`，`sign = -1`；`d < 0` 时从 `max` 面进入，外法线是 `+axis`，`sign = +1`；
- 没有单独的 `tmax < 0` 判断，但因为 `tmin` 初值是 0，盒子在射线背后时必然 `tmin > tmax`，会提前返回；
- `hitAxis` 只在 `t1 > tmin` 时更新，所以法线来自"最后进入"的那个面，符合直觉。
### 4.3 球 vs AABB：最近点
球心 `c`、半径 `r`，盒子 `[min, max]`。把球心夹到盒子上，得到盒子上离球心最近的点：

```
closest = clamp(c, min, max)
diff = c - closest
distSq = dot(diff, diff)
if (distSq > r²) 不相交
if (distSq > 1e-8) {
    n = diff / sqrt(distSq)
    depth = r - sqrt(distSq)
} else {
    // 球心在盒内：分别算三个轴的最小穿透，选最小的那个
}
```

`PhysicsWorldSim.cpp` 的 `SphereVsBox` **已实现**这套逻辑，包括球心在内部时选最小穿透轴。第三人称控制器里的 `ResolveCollisions` 是它的简化版：没有内部退化处理；而且它用三维距离 `distance` 判断，却只把法线的 y 清零后做 XZ 推出，推离量会偏小（详见第 15 讲）。

`WaveGame.cpp` 的 `MoveWithSlide` 是更干净的"圆柱 vs AABB"：只取 XZ 最近点，`distance < radius` 就沿水平方向推出。它不处理竖直，竖直交给地面射线。
### 4.4 射线 vs 球：一元二次方程
把射线代入球方程 `|o + d·t - c|² = r²`：

```
a = dot(d, d)
b = 2·dot(o - c, d)
c0 = dot(o - c, o - c) - r²
Δ = b² - 4·a·c0
```

`Δ < 0` 无交点；否则 `t = (-b ∓ sqrt(Δ)) / (2a)`。取较小的非负根；如果较小的根为负、较大的根为正，说明起点在球内，取较大的根作为出射点。

`Math.h` 的 `IntersectRaySphere` **已实现**这个求交；`PhysicsWorld::RaySphere` 只是转调它，当前**没有调用者**。AI 视线用的是 AABB `Raycast`，不是这个函数；刷怪子弹用的是距离阈值，也不是严格的球-球（没有读取目标半径）。这三件事（射线-球求交、AI 视线、子弹命中）要分开看，不能混成同一个"球-球/射线-球"测试。
### 4.5 空间划分
射线查询是 `O(n)`，碰撞是球两两 `O(n²)`、每个动态体对每个静态盒 `O(n·m)`。对象一多，先要减少"候选对"：

| 结构 | 适合 | 构建 | 查询 |
|---|---|---|---|
| 均匀网格 | 分布均匀的场景 | `O(n)` | 格子内物体数 |
| 四叉/八叉树 | 静态场景 | `O(n log n)` | 平均 `O(log n)` |
| BVH | 动态/静态混合，可并行 | `O(n log n)` | 平均 `O(log n)` |
| 哈希网格 | 稀疏大世界 | `O(n)` 均摊 | `O(1)` 均摊 |

本工程的导航用了**均匀栅格**：`NavGrid::Build` 以 `0.5 m` 为格、范围 `[-25, 25]`，把静态刚体的 XZ footprint 加角色半径后栅格化（`NavGrid.cpp:16-65`）。但这是给 A* 寻路用的，不是射线查询的宽相；`World::Raycast` 仍然逐个物体扫。物理也没有宽相。
### 4.6 本工程到底有哪些查询

| 查询 | 状态 | 说明 |
|---|---|---|
| `World::Raycast(ray, maxDistance, hit, ignore = nullptr)` | 已实现 | 只对网格的**世界 AABB** 求交，返回最近命中；可选 `ignore` 在求交前跳过指定对象（角色自检用） |
| `World::GetObjectBounds` | 已实现 | 单个物体的世界 AABB |
| `World::CollectMeshAABBs` | 已实现 | 收集所有活动网格 AABB；常被调用方拿来自己做重叠查询 |
| `IntersectRayAABB` | 已实现 | slab 法；起点在盒内返回 `t=0` |
| `IntersectRaySphere` / `PhysicsWorld::RaySphere` | 已实现 | 解析二次方程；当前无调用者 |
| `SphereVsBox` | 已实现 | 物理内部使用；含球心在盒内的最小穿透轴 |
| OBB / SAT | 尚未实现 | `Math.h` 没有 `OBB` 类型 |
| 独立的 Overlap / SphereCast / CapsuleCast | 尚未实现 | 没有 `World::Overlap` 之类的 API |
| 三角形级射线、网格精确拾取 | 尚未实现 | 所有拾取都停在 AABB |
| 宽相 / BVH / 射线加速结构 | 尚未实现 | `Raycast` 是线性扫描 |

从角色身体内部发出的射线必须把角色传给 `ignore`：`IntersectRayAABB` 对盒内起点返回 `tmin=0`，
只在命中后比较 `hit.object` 并不能继续找平台，因为 `t=0` 的自命中已经占住了最近命中。

所以"鼠标点中物体"确实存在，但精度到 AABB；"角色撞墙"也存在，但用的是 `CollectMeshAABBs` + 手写推离；"AI 视线"是 AABB 射线；"子弹命中"是距离阈值。不要把它们都叫成"物理引擎的碰撞查询"。

`BuildWorldAABB` 的关键选择是：**包围盒来自 `MeshRenderer` 的网格，不是 `RigidBodyComponent` 的形状**。所以：

- 物体没有 `MeshRenderer` 或网格资源无效时，查询直接跳过它；
- 物理盒的 `halfExtents` 和渲染网格的尺寸可以不一致，查询与物理会各算各的；
- 8 个角点变换后再取 min/max，旋转后的 AABB 一定比原 AABB 大（3.1）。
## 6. 数值例子：射线-AABB 的 `tmin/tmax`
下面手算一遍（不是引擎日志）。射线 `o = (0, 1, 5)`，方向 `d = (0, 0, -1)`；盒子 `min = (-1, 0, 2)`，`max = (1, 2, 4)`。

| 轴 | 计算 | 结果 |
|---|---|---|
| x | `d.x = 0`，`o.x = 0 ∈ [-1, 1]` | 不约束，跳过 |
| y | `d.y = 0`，`o.y = 1 ∈ [0, 2]` | 不约束，跳过 |
| z | `t1 = (2-5)/(-1) = 3`，`t2 = (4-5)/(-1) = 1` | 交换后 `t1 = 1, t2 = 3` |

所以 `tmin = 1`、`tmax = 3`，`tmin <= tmax`，命中。命中点是

```
o + d·tmin = (0, 1, 5) + (0, 0, -1)·1 = (0, 1, 4)
```

正好在盒子的 `z = 4` 面上；`d.z < 0`，是从 `max` 面进入的，外法线是 `(0, 0, +1)`，代码里 `sign = +1`。距离是 1（因为 `d` 是单位向量）。

再看两个边界：

- 起点在盒内 `o = (0, 1, 3)`：x/y 不约束；z 的 `t1 = (2-3)/(-1) = 1`，`t2 = (4-3)/(-1) = -1`，交换后 `t1 = -1, t2 = 1`。`t1 > tmin(0)` 不成立，所以 `tmin` 保持 0，`tmax = 1`，返回 `t = 0`，法线为零向量。**这就是"射线打中自己"的数学来源。**
- 起点在盒外且平行轴不重叠 `o = (0, 3, 5)`：y 轴 `d = 0`，`o.y = 3 > 2`，直接返回 false。
## 7. 边界与工程取舍

| 项 | 现状 | 状态 |
|---|---|---|
| AABB 求交 / slab 射线 | 球、盒、网格包围盒 | 已实现 |
| 旋转物体紧包围盒（OBB/SAT） | 无 | 尚未实现 |
| 网格三角形级拾取 | 无 | 尚未实现 |
| 射线过滤（ignore / layer mask） | 无；`Raycast` 没有 ignore 参数 | 尚未实现 |
| 重叠 / 球扫掠 / 胶囊扫掠 | 无独立 API | 尚未实现 |
| 宽相 / BVH / 网格加速 | `Raycast` 线性；物理无宽相 | 尚未实现 |
| 连续碰撞（CCD） | 无 | 尚未实现 |

两个最实际的坑：

1. **`Raycast` 没有 ignore 列表。** 起点在角色自己的 AABB 内时，最近命中就是角色本身（`t=0`），调用方只能事后比较 `hit.object`，不能"跳过自己继续找后面的物体"。第三人称地面检测就受影响，详见第 15 讲。
2. **AABB 与真实几何不一致。** 旋转薄板、圆环、拱门都会被当成实心盒子；拾取和视线都会出现"点空气命中"。
## 8. 实验
> 本环境是 Linux，不能运行 Windows 的 `ErMao.exe`；下面是**本次未实际运行**的条件性预期。

```bat
build\bin\ErMao.exe --level demo --frames 60          :: 拾取：点木箱/旋转雕塑
build\bin\ErMao.exe --level thirdperson --play         :: 撞墙、地面射线
build\bin\ErMao.exe --level arena --play               :: 子弹命中/穿透
```

1. **拾取假阳性**：在 `demo` 关卡里点旋转雕塑（`torus`）旁边的空气。按 AABB 逻辑，只要射线穿过它的世界 AABB 就会选中它，即使实际几何是空心的。若点不中，检查该物体是否有 `MeshRenderer`、网格资源是否有效。
2. **薄板遮挡**：找一个旋转过的薄物体（或把木箱 `rotation.y` 调到 45°），从侧面点它旁边的空气；预期更容易误选，因为 AABB 膨胀了。
3. **子弹穿透**：在 `arena` 里把 `projectileSpeed` 从 34 调到 100，对着敌人开火。按 100/60 ≈ 1.67 m 的每帧位移、0.75 m 的判定半径，预期经常打不中；调回 34 则更容易命中。这不是射线查询的问题，是 `OnUpdate` 的点采样。
4. **角色撞墙**：在 `thirdperson` 里按住 W 撞矮墙，预期停住并沿墙滑动；如果穿过去，检查墙是否有静态 `RigidBodyComponent`、`CollectMeshAABBs` 是否收集到了它。
5. **验证"打中自己"**：在 `ThirdPersonController` 的地面检测前临时打一条日志，打印 `hit.object->Name()`。按本讲分析，起点在角色 AABB 内时应先命中"玩家"；如果日志确实是"玩家"，就说明地面射线需要 ignore 列表。本次未运行，不能替你确认。
6. **AI 视线**：让巡逻者隔着立柱看玩家，预期视线被立柱的 AABB 挡住；把立柱换成更细的网格，AABB 仍然很粗，遮挡范围不会跟着变细。

排查顺序：物体是否 `Active()`、是否有 `MeshRenderer`、网格 `IsValid()`、射线方向是否归一化、`maxDistance` 是否够大、起点是否已经在目标 AABB 内。
## 9. 自测题
1. 写出射线-AABB 的 `tmin/tmax` 更新，并说明为什么 `d.x = 0` 要单独处理。**答案**：见 2.2 / 4.2；平行轴不能除，原点在板外直接不相交。
2. 旋转 45° 的立方体，世界 AABB 体积变成多少倍？**答案**：见 3.1；边长 1 的立方体绕 Y 转 45° 后 XZ 各为 1.414，体积 2 倍。
3. 球心在 AABB 内部时最近点法会怎样？本工程怎么处理？**答案**：见 4.3；`diff = 0`，方向退化；`SphereVsBox` 选最小穿透轴，控制器则跳过。
4. 弹速 34 m/s、判定半径 0.75 m，为什么 30 fps 下可能打不中？**答案**：见 3.3；每帧位移 1.133 m > 0.75 m，采样点之间漏检。
5. 本工程有没有 `World::Overlap` 或 OBB 查询？**答案**：见 4.6；没有，只有 AABB `Raycast`/`CollectMeshAABBs`/`GetObjectBounds` 和内部的 `SphereVsBox`。
## 练习（故意改坏）
1. 把 slab 里的 `tmax = min(tmax, t2)` 改成 `tmax = max(tmax, t2)`：**预期**区间永远不闭合，射线会"命中"盒子后面的所有东西。
2. 删掉平行轴判断：**预期** `d=0` 时除零得到 `±inf` 或 `NaN`，不同编译器/优化级别下结果不一致。
3. 把 `tmin` 初值从 0 改成 `-FLT_MAX`：**预期**起点在盒内时返回负距离，调用方会得到"命中点在身后"。
4. 把 `BuildWorldAABB` 的 8 角点变换改成只变换中心：**预期**旋转物体的 AABB 不再随旋转变大，剔除/拾取会误判。
5. 删掉控制器里的 `distance > 1e-4f` 保护：**预期**球心进入盒子内部时法线除以 0，角色位置变成 `NaN`。
